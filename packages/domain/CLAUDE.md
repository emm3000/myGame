# packages/domain

The game rules as pure TypeScript (ADR 004). Everything else depends on this package; it depends on nothing.

## Commands

- `pnpm --filter @mygame/domain typecheck` — `tsc --noEmit` over `src` and the Vitest config.
- `pnpm --filter @mygame/domain test` — Vitest, runs `src/**/*.test.ts`.
- `pnpm gate` from the repo root before every commit.

## Entry

`src/index.ts` is the only entry. Consumers import from `@mygame/domain`, never from a path under `src`.

## Gotchas

- Zero runtime dependencies. `typescript` and `vitest` are dev dependencies taken from the workspace `catalog:`; `jq '.dependencies' package.json` prints `null`.
- No `node:` imports, no framework, no `zod`. The leak check in `.claude/rules/architecture.md` must stay empty.
- No comments of any kind, including JSDoc. The narrow exceptions are in `.claude/rules/typescript-style.md`.
- Explicit return type on every exported function, method and exported arrow.
- Nothing throws. A failure is a member of the `DomainError` union returned inside a `Result`; `rg -n "extends Error|throw new" src` stays empty, test files included. In a test, narrow a `Result` with Vitest's `assert(result.ok)` instead of throwing.
- Time comes only from the `Clock` port. `Date.now()`, `new Date()`, `setTimeout` and `setInterval` never appear in `src`, tests included; a test builds a `frozenClock` beside itself.
- `Instant` is stored as epoch milliseconds; `Duration` is whole or fractional seconds and never negative.
- A busy `BuildSlot` carries `cost`, the stocks the enqueue debited, taken from the same catalog line as the debit. Whatever needs what a running upgrade cost reads it there, never the catalog, which may have changed since the enqueue (N5).
- `Fief` carries its `buildQueue`, the entries waiting behind the slot in order, each with the building, target level, debited cost and duration fixed at the enqueue (ADR 011). `Fief.restore` reads no catalog, so it cannot check the content cap `FiefSettings.buildQueueCap`; it refuses an entry whose duration is negative (`NegativeDuration`) or not whole seconds (`FractionalDuration`).
- `Fief.enqueueUpgrade(entry, stocksAtNow, now, buildQueueCap)` is the only way an upgrade is enqueued: an idle slot with nothing waiting takes it, otherwise it joins the end of the queue, and a full queue refuses `QueueFull` (`Fief.roomForUpgrade`). Either way it debits the cost at `now`. `enqueueBuilding` checks the room first, then judges the target level, `MaxLevelReached` and the peasants on `Fief.projectedBuildingLevels` (built levels with the slot and every waiting entry applied) through `deriveProjectedFreePeasants`, the free count of `derivePeasantCounts(levels, units, recruitOrder, catalog)`, which answers the peasant trio (supplied, occupied, free) at any building levels, adds each unit count, and an open recruit order's `count`, times `FiefSettings.units[kind].peasantOccupancy` to the occupied peasants (`FiefUnitCounts`, every kind at 0 on `found`, restored through its invariant factory or refused with `InvalidUnitCount`), and is what the overview reads for both the built and the projected counts.
- `Fief.cancelUpgrade(target, stocksAtNow, now, catalog)` is the only upgrade cancel. It answers a `ChangedFief` (`{ fief, events }`): one `upgradeCancelled` for the named entry, then one per entry dropped in cascade in queue order, each refunding the cost it stored, all at the cancel instant (`revalidateBuildQueue` answers the `dropped` entries; `refundOf` sums them); the `cancelUpgrade` use case answers the same. `target` is an `UpgradeTarget` (`building`, `targetLevel`), unique across the slot and the queue, so a stale screen can never cancel a neighbour. It refuses `UpgradeNotFound` when the slot has finished by `now` (`isSlotFinishedBy`, the one predicate `resolveUpgrade` shares) or when neither the slot nor the queue holds the target. It refunds the entry's stored cost, then revalidates the remaining entries with `entryFitsProjection` from the built levels plus the slot still busy, refunding every entry dropped in cascade, and starts the first kept entry at `now` when the slot was the one cancelled.
- Known gap: if the catalog loses a level after its enqueue, `derivePeasantsForUpgrade` answers `UnknownBuildingLevel` and every read of that fief fails; the enqueue projection and the cancel cascade share it.
- `scheduleBuildQueue(slot, buildQueue)` chains the waiting entries: the first starts at the slot's `finishesAt`, each next one when the one before finishes. Behind an idle slot it schedules nothing.
- `resolveUpgrade` first restarts a build queue left behind an idle slot (`Fief.isSlotIdleWithQueue`, which only a cancel stored before #92 left behind). `Fief.resumeBuildQueue(catalog)` revalidates the entries in order against the projection with `entryFitsProjection`: the target level must be the projected level plus one, and the peasant increase must fit the projected free peasants, read through `derivePeasantCounts`. A projection with more occupied than supplied peasants does not fit, so the entry is dropped, while the enqueue refuses the same case with `NegativeFreePeasants`. Every entry that no longer fits is dropped, and its cost is refunded to the stocks at `storedAt`. The first entry that fits starts at `storedAt`, the cancel instant. It then walks one timeline: while the earliest finish among the busy build slot, the busy study slot, the open recruit order's end (`recruitOrderEndsAt`, `startedAt + count × perUnitSeconds`) and an away march's return (`marchInstantsOf(march).returnsAt`) is at or before `now`, it materializes the stocks to that finish at the building and art levels in force. `Fief.completeUpgrade` applies an upgrade finish (the level, and the first waiting entry moves into the slot, started at that finish and finishing its stored duration later) and `Fief.completeStudy` applies a study finish (the art rises to `targetLevel`, the study slot idles) and `Fief.completeRecruitOrder` closes an ended order (its `count` moves into the unit counts, the recruit slot idles, so the occupied peasants do not change) and `Fief.completeMarch` closes a returned march (its `loot` is credited to the stocks materialized to `returnsAt`, even above the capacity, where they freeze; `storedAt = returnsAt`; the march slot idles; no unit count and no peasant changes, since the infantry away were counted all along). On a tie the upgrade applies first, then the study, then the order, then the march, and their events follow that order, so a `marchReturned` comes last among the events of a tied instant. The early return checks the four through `earliestFinishedOf`, and `isSlotFinishedBy` takes either busy slot. An order still delivering is never touched: `deliveredUnitsOf(order, at)` is `min(count, floor(elapsed / perUnitSeconds))`, derived on read and never stored, and `Fief.unitCountsAt(at)` answers the stored counts plus those delivered units. Each walk step floors the stocks, so an order closing between two finishes can cost a unit per resource, as any finish does. `materializeStocks` splits every span at each season boundary it crosses, the epoch included (`nextSeasonBoundaryAfter` in `season/`), and accrues each segment with `accrue` at `deriveResourceRates` for the segment's start: k boundaries make k + 1 segments, each floored and clamped on its own, so a read may land up to one unit per boundary below the unfloored sum. A finish and a boundary order themselves by instant, since each walk step is one more materialization. The walk stops at the first upgrade still building; with nothing left the slot is idle. It accrues to `now`, or to the fief's `storedAt` when that is later. `hasChanged` is true when the read restarted the queue, completed at least one upgrade or study, closed an order or closed a march. `ResolvedFief` is `ChangedFief & { hasChanged }`: one event per finish the walk applied, in walk order (upgrade first on a tie), each at its `finishesAt`, never `now`; `events: []` when `hasChanged` is false, one `recruitsDelivered` per closed order, one `marchReturned` per closed march, and no event for the entries `resumeBuildQueue` drops.
- `BuildingKind` has seven members; `library` levels are a `LibraryLevel` and `barracks` levels a `BarracksLevel` (cost, duration, occupancy, no effect), so every `FiefBuildingLevels` fixture carries a `library` and a `barracks` key. The built barracks level gates and divides recruiting (below).
- `Fief` carries `studySlot` (`StudySlot`, idle on `found`): idle, or busy with `art`, `targetLevel`, `startedAt`, `finishesAt` and the `cost` it debited, mirroring the busy `BuildSlot`. `Fief.restore` refuses a busy study whose target level is below 1 (`InvalidArtLevel`), that finishes before `storedAt`, that starts after it finishes, or that holds a negative cost, with the same members as the build slot (`validateTimedWork`). Every `StoredFief` fixture carries a `studySlot` key.
- `Fief` carries `recruitOrder` (`RecruitOrder`, idle on `found`): idle, or open with `unit`, `count`, the `cost` it debited (the unit's cost times `count`), `perUnitSeconds` and `startedAt`; one order at a time, no queue. `Fief.restore` refuses an open order whose `count` is not a whole count from 1 (`InvalidUnitCount`), whose `perUnitSeconds` is not (`InvalidUnitDuration`), whose cost is negative (`NegativeResourceAmount`), or that ends before `storedAt` (`SlotFinishesBeforeStored`, with the order's end as `finishesAt`). Every `StoredFief` fixture carries a `recruitOrder` key. `Fief.placeRecruitOrder({ unit, count, terms }, stocksAtNow, now, trainPercent)` is the only way an order opens: it refuses `InvalidUnitCount` (below 1 or fractional), then `BarracksNotBuilt` (built barracks at 0), then `RecruitSlotBusy`, then `InsufficientResources`; it debits at `now` and fixes `perUnitSeconds = deriveUnitDurationSeconds(terms.durationSeconds, barracksLevel, trainPercent)`, `ceil(durationSeconds * trainPercent / (100 * (1 + barracksLevel)))` with one rounding, at the built level, never the projected one. The `Fief` reads no calendar: the use case hands it the `train` percent of `durationPercentAt` at `clock.now()`, as `startStudy` hands the study percent, and that one duration holds for every unit of the order; an order that runs into another season is never retimed, since the resolve reads the stored `perUnitSeconds`. The use case `placeRecruitOrder({ playerId, unit, count })` then refuses `NotEnoughPeasants` when `count` times the unit's occupancy exceeds the lesser of the built and the projected free peasants, since either alone could drive the other trio negative. The order occupies every unit's peasants from the instant it is placed, delivered or not; the build slot, the build queue and the study slot are untouched. Delivery and its close are in the resolve gotcha; the api stores the counts in `fief_units` and the open order in `fief_recruit_orders`.
- Known gap: neither `Fief.restore` nor `completeStudy` checks a study's `targetLevel` against the current art level or the catalog; a stored study that targets a level the catalog lacks makes every read after its finish fail with `UnknownArtLevel`, like the building gap above.
- `Fief.startStudy(line, stocksAtNow, now, studyPercent)` is the only way a study starts. It refuses `StudySlotBusy` (a study runs), then `LibraryLevelTooLow` (the built `library` level is below the line's `requiredLibraryLevel`, level 0 included), then `InsufficientResources`. It debits the line's cost at `now` and touches neither the build slot, the build queue nor the peasants. The use case `startStudy` reads `nextArtLevelOf(art, level, catalog)` first and answers `ArtMaxLevelReached` when there is no next line. `deriveStudyDurationSeconds(durationSeconds, libraryLevel, studyPercent)` is `ceil(durationSeconds * studyPercent / (100 * (1 + libraryLevel)))` at the built library level, never the projected one: one division and one `ceil`, never a rounding per factor (1000 s at library 2 in a 75 % winter is 250, where two roundings give 251). The use case hands `Fief.startStudy` the study percent of `durationPercentAt(now, settings)`, so the `Fief` reads no calendar; the overview reads the same function at `storedAt`. `deriveBuildDurationSeconds(durationSeconds, buildPercent)` is `ceil(durationSeconds * buildPercent / 100)`; `enqueueBuilding` stores it on the entry with the build percent at `now`, whether the entry takes the slot or waits, and nothing retimes a stored entry or a running study when the season turns (ADR 011). A positive duration never scales below 1 second; a duration of 0 stays 0. `artLevelInForce(art, level, catalog)` answers the line in force (`undefined` at level 0, `UnknownArtLevel` for a missing or mismatched line), read by `deriveResourceRates` and the overview. `artResourceOf(art, catalog)` answers the resource the art's level-1 line raises (`UnknownArtLevel` with `level: 1` when that line is missing or mismatched), read by the overview; both share the guard in `artLineOf`.
- `Fief.cancelStudy(target, stocksAtNow, now)` is the only study cancel. It and the `cancelStudy` use case answer a `ChangedFief` with one `studyCancelled` refunding the study slot's stored cost at the cancel instant. `target` is a `StudyTarget` (`art`, `targetLevel`). It refuses `StudyNotFound` when the study slot is idle, holds another art or level, or has finished by `now` (`isSlotFinishedBy`). It credits the slot's stored `cost` to `stocksAtNow`, even above the capacity, stamps `storedAt = now` and idles the study slot; no cascade, and the build slot, the build queue and the art levels are untouched. The use case `cancelStudy({ playerId, art, targetLevel })` materializes the stocks at `now` first.
- `Fief.cancelRecruitOrder(target, stocksAtNow, now)` is the only recruit cancel. `target` is a `RecruitOrderTarget` (`unit`, `startedAt`). It refuses `RecruitOrderNotFound { unit, startedAt }` when the recruit slot is idle, holds another unit or another `startedAt`, or the order has ended by `now` (`recruitOrderEndsAt` at or before `now`, left for the resolve to close). Otherwise it adds `deliveredUnitsOf(order, now)` to the unit's stored count, so a delivery at exactly `now` is kept, credits `cost × (count − delivered) / count` per resource to `stocksAtNow`, even above the capacity and with no rounding (the stored cost is `count` times the unit cost, since seasons scale only durations), stamps `storedAt = now` and idles the recruit slot. The undelivered units' peasants are freed by derivation, nothing stored; no cascade, and the build slot, the build queue, the study slot and the levels are untouched. It and the `cancelRecruitOrder({ playerId, unit, startedAt })` use case answer a `ChangedFief` with one `recruitsCancelled` at the cancel instant, with the units delivered, `cancelled = count − delivered` and the refund it credited; the use case materializes the stocks at `now` first and records like `cancelStudy`.
- Known gap: `cancelUpgrade`, `enqueueBuilding`, `startStudy`, `cancelStudy`, `placeRecruitOrder` and `cancelRecruitOrder` open the same way (load the fief, `FiefNotFound`, `materializeStocks` at `now`, mutate, save), six copies awaiting one shared opening.
- `FiefEvent` (`fief/FiefEvent.ts`) is a union on `kind`: `upgradeFinished` (`building`, `level`, `occurredAt`), `artLearned` (`art`, `level`, `occurredAt`), `upgradeCancelled` and `studyCancelled` (the same plus `refund`, a `Stocks`), and `recruitsDelivered` (`unit`, `count`, `occurredAt`), which the resolve answers once per order it closes, with the order's `count`, stamped with its last delivery (`recruitOrderEndsAt`), never per unit delivered, and `recruitsCancelled` (`unit`, `delivered`, `cancelled`, `occurredAt`, `refund`), which the recruit cancel answers once, at the cancel instant, and `marchReturned` (`province`, `plot`, `infantry`, `loot`, `occurredAt`), which the resolve answers once per march it closes, stamped with `returnsAt`, never while the march is away. `level` is the level reached or the target level cancelled. A refused call answers an error and no event. `ChronicleWriter` (`ports/ChronicleWriter.ts`) receives them: `resolveUpgrade`, `cancelUpgrade`, `cancelStudy` and `cancelRecruitOrder` take `chronicle` and call `record(fief.id, events)` right after `fiefs.save` succeeds, never when they save nothing. The domain never reads the chronicle. Tests pass `inMemoryChronicle()` (`testing/inMemoryChronicle.ts`, `recordedEventsOf(fiefId)`) or `refusingChronicle()`.
- `BuildingCatalog.artLevelOf(art, level)` answers an `ArtLevel` (`art`, `level`, `cost`, `durationSeconds`, `requiredLibraryLevel`, `resource`, `ratePercent`) or `undefined`. Every `BuildingCatalog` fake in the domain and api tests must implement it; `() => undefined` suffices where no art is studied.
- `Fief` carries `artLevels` (`FiefArtLevels`, with every `ArtKind` at 0 on `found`). `Fief.restore` refuses an art level that is negative or not whole with `InvalidArtLevel`. `artKinds` derives from a `Record<ArtKind, true>`, so a new art does not compile until it is listed.
- `deriveResourceRates(buildingLevels, artLevels, terrain, catalog, at)` sums base, producers and terrain. Then it collects the whole percents that scale each resource: `100 + ratePercent` of each art above level 0 on its line's `resource`, then, last, the percent of the season in force at `at` for every resource, so the season scales the terrain bonus and the arts too; before the epoch there is no season percent. Each rate is scaled once, as `rate * (product of its percents) / 100 ** count`: never `rate * (1 + ratePercent / 100)`, which falls short in floating point (200/h at 15 % would give 229.99…), and never one division per percent, which drifts too (31/h with a 5 % art in a 125 % season would give 40.68749…, not 40.6875). A missing or mismatched art line answers `UnknownArtLevel`. Level 0 reads no line. `materializeStocks` derives the rates anew at the start of each season segment (see the resolve gotcha).
- `FiefSettings.seasons` is a `SeasonCalendar` (`season/SeasonCalendar.ts`): `epoch` (an `Instant`), `daysPerSeason`, `multiplierPercent`, a whole percent per `SeasonKind` and resource, and `durationPercent`, a `DurationPercent` (`{ build, study, train }`, whole percents) per `SeasonKind`. `durationPercentAt(instant, settings)` (`season/durationPercentAt.ts`) answers the `DurationPercent` in force, `{ build: 100, study: 100, train: 100 }` before the epoch; rates never read it and durations never read `multiplierPercent`. `seasonAt(instant, settings)` (`season/seasonAt.ts`) answers the `Season` in force (`kind`, `year`, `endsAt`) or `undefined` before the epoch: spring of year 1 starts at the epoch, the seasons run spring, summer, autumn, winter, and a season runs from its start, included, to its `endsAt`, excluded. Every `FiefSettings` fixture carries `seasons`; `testing/neutralSeasons.ts` is a calendar with every cell at 100, for tests that are not about seasons.
- `FiefSettings.forage` is `ForageTerms` (`secondsPerProvince`, `secondsPerPlot`, `carryPerInfantry`, `maxStayHours`, `yieldPerHour` per `Terrain` and resource). `marchOneWaySeconds(from, to, forage)` and `forageLootOf(terrain, infantry, stayHours, forage)` in `march/` read no clock and no season; the loot splits the carry evenly among the resources the terrain yields above 0, each floored, and never forages gold whatever the terms say. Every `FiefSettings` fixture carries `forage`; `testing/plainForage.ts` holds the shipped terms.
- `Fief` carries `march` (`March` in `march/March.ts`, idle on `found`): idle, or away with `province`, `plot`, `infantry`, `stayHours`, `departedAt`, `oneWaySeconds` and the `loot` fixed at dispatch; one march at a time. `Fief.restore` refuses an away march whose `infantry` is not a whole count from 1 (`InvalidUnitCount`), whose `stayHours` is not (`StayOutOfRange`), whose `oneWaySeconds` is negative or fractional (`NegativeDuration`, `FractionalDuration`) or whose loot is negative (`NegativeResourceAmount`); it does not check the infantry away against the counts. An away march that returns before `storedAt` is refused too (`SlotFinishesBeforeStored`, with `returnsAt` as `finishesAt`). Every `StoredFief` fixture carries a `march` key. `marchInstantsOf(march)` answers `arrivesAt = departedAt + oneWaySeconds`, `leavesAt = arrivesAt + stayHours × 3600` and `returnsAt = leavesAt + oneWaySeconds`; `marchPhaseAt(march, at)` answers `outbound`, `foraging` or `returning`, an instant equal to a boundary reading the later phase. Both derive on read and nothing is stored per phase; the resolve closes the march at `returnsAt`. `Fief.unitsAtHomeAt(at)` is `unitCountsAt(at)` less an away march's infantry. `Fief.roomForMarch(order, maxStayHours)` refuses `InvalidUnitCount`, then `StayOutOfRange` (outside 1..`maxStayHours`), then `MarchSlotBusy`; `Fief.dispatchMarch(order, now, forage)` checks the room again, refuses `NotEnoughInfantryAtHome`, and stores the march with `departedAt = now`, `marchOneWaySeconds` from the fief's coordinates and `forageLootOf` on `terrainOf(province)`. The use case `dispatchMarch({ playerId, province, plot, infantry, stayHours })` takes `fiefs`, `map`, `catalog` and `clock` and refuses in order: the room, `MarchTargetOutOfBounds` (a province outside 1..`lastOccupiedProvince + 1` or a plot outside 1..`plotsPerProvince`), `MarchToOwnPlot`, `PlotHeld` (`holdersIn` lists it), then `NotEnoughInfantryAtHome`. No debit, no stamp of `storedAt`: the infantry away stay counted and keep their peasants, and the build slot, the build queue, the study slot and the recruit slot are untouched. The api stores an away march in `fief_marches`, one row per fief, and no row is an idle march slot.
- Imports are extensionless (`'./Duration'`); the base tsconfig resolves as `Bundler` without `allowImportingTsExtensions`.
- `KingdomMapReader` (`ports/KingdomMapReader.ts`) is the map's read port: `addressOf(playerId)`, `lastOccupiedProvince(kingdom)` (0 when no fief), `holdersIn(kingdom, province)` answering `PlotHolder`s (`plot`, `name`, `playerId`). Its methods answer plain values, not a `Result`, like `FiefRepository.occupiedPlots`. Tests pass `inMemoryKingdomMap(heldPlots)` (`testing/inMemoryKingdomMap.ts`).
- `readProvinceMap({ playerId, province? }, { map, catalog })` answers a `ProvinceMap` (`kingdom/ProvinceMap.ts`). `lastProvince` is `lastOccupiedProvince + 1`, so the province past the last held one opens empty; a province below 1, not whole or above it refuses `ProvinceNotFound { province, lastProvince }`. Plots run 1..`plotsPerProvince`; a holder on a higher plot is not listed.
- `terrainOf(province)` takes the province number; the terrain belongs to the province, not the plot.
