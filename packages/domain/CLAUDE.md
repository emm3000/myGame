# packages/domain

The game rules as pure TypeScript (ADR 004). Everything else depends on this package; it depends on nothing.

## Commands

- `pnpm --filter @mygame/domain typecheck` — `tsc --noEmit` over `src` and the Vitest config.
- `pnpm --filter @mygame/domain test` — Vitest, runs `src/**/*.test.ts`.
- `pnpm gate` from the repo root before every commit.

## Entry

`src/index.ts` is the only entry. Consumers import from `@mygame/domain`, never from a path under `src`.

## Gotchas

- Zero runtime dependencies. `typescript` and `vitest` are dev dependencies taken from the workspace `catalog:`; `jq '.dependencies' package.json` prints `null`.
- No `node:` imports, no framework, no `zod`. The leak check in `.claude/rules/architecture.md` must stay empty.
- No comments of any kind, including JSDoc. The narrow exceptions are in `.claude/rules/typescript-style.md`.
- Explicit return type on every exported function, method and exported arrow.
- Nothing throws. A failure is a member of the `DomainError` union returned inside a `Result`; `rg -n "extends Error|throw new" src` stays empty, test files included. In a test, narrow a `Result` with Vitest's `assert(result.ok)` instead of throwing.
- Time comes only from the `Clock` port. `Date.now()`, `new Date()`, `setTimeout` and `setInterval` never appear in `src`, tests included; a test builds a `frozenClock` beside itself.
- `Instant` is stored as epoch milliseconds; `Duration` is whole or fractional seconds and never negative.
- A busy `BuildSlot` carries `cost`, the stocks the enqueue debited, taken from the same catalog line as the debit. Whatever needs what a running upgrade cost reads it there, never the catalog, which may have changed since the enqueue (N5).
- `Fief` carries its `buildQueue`, the entries waiting behind the slot in order, each with the building, target level, debited cost and duration fixed at the enqueue (ADR 011). `Fief.restore` reads no catalog, so it cannot check the content cap `FiefSettings.buildQueueCap`; it refuses an entry whose duration is negative (`NegativeDuration`) or not whole seconds (`FractionalDuration`).
- `Fief.enqueueUpgrade(entry, stocksAtNow, now, buildQueueCap)` is the only way an upgrade is enqueued: an idle slot with nothing waiting takes it, otherwise it joins the end of the queue, and a full queue refuses `QueueFull` (`Fief.roomForUpgrade`). Either way it debits the cost at `now`. `enqueueBuilding` checks the room first, then judges the target level, `MaxLevelReached` and the peasants on `Fief.projectedBuildingLevels` (built levels with the slot and every waiting entry applied) through `deriveProjectedFreePeasants`, the free count of `derivePeasantCounts`, which answers the peasant trio (supplied, occupied, free) at any building levels and is what the overview reads for both the built and the projected counts.
- `Fief.cancelUpgrade(target, stocksAtNow, now, catalog)` is the only upgrade cancel. It answers a `ChangedFief` (`{ fief, events }`): one `upgradeCancelled` for the named entry, then one per entry dropped in cascade in queue order, each refunding the cost it stored, all at the cancel instant (`revalidateBuildQueue` answers the `dropped` entries; `refundOf` sums them); the `cancelUpgrade` use case answers the same. `target` is an `UpgradeTarget` (`building`, `targetLevel`), unique across the slot and the queue, so a stale screen can never cancel a neighbour. It refuses `UpgradeNotFound` when the slot has finished by `now` (`isSlotFinishedBy`, the one predicate `resolveUpgrade` shares) or when neither the slot nor the queue holds the target. It refunds the entry's stored cost, then revalidates the remaining entries with `entryFitsProjection` from the built levels plus the slot still busy, refunding every entry dropped in cascade, and starts the first kept entry at `now` when the slot was the one cancelled.
- Known gap: if the catalog loses a level after its enqueue, `derivePeasantsForUpgrade` answers `UnknownBuildingLevel` and every read of that fief fails; the enqueue projection and the cancel cascade share it.
- `scheduleBuildQueue(slot, buildQueue)` chains the waiting entries: the first starts at the slot's `finishesAt`, each next one when the one before finishes. Behind an idle slot it schedules nothing.
- `resolveUpgrade` first restarts a build queue left behind an idle slot (`Fief.isSlotIdleWithQueue`, which only a cancel stored before #92 left behind). `Fief.resumeBuildQueue(catalog)` revalidates the entries in order against the projection with `entryFitsProjection`: the target level must be the projected level plus one, and the peasant increase must fit the projected free peasants, read through `derivePeasantCounts`. A projection with more occupied than supplied peasants does not fit, so the entry is dropped, while the enqueue refuses the same case with `NegativeFreePeasants`. Every entry that no longer fits is dropped, and its cost is refunded to the stocks at `storedAt`. The first entry that fits starts at `storedAt`, the cancel instant. It then walks one timeline: while the earliest finish among the busy build slot and the busy study slot is at or before `now`, it materializes the stocks to that finish at the building and art levels in force. `Fief.completeUpgrade` applies an upgrade finish (the level, and the first waiting entry moves into the slot, started at that finish and finishing its stored duration later) and `Fief.completeStudy` applies a study finish (the art rises to `targetLevel`, the study slot idles). On a tie the upgrade applies first. The early return checks both slots through `earliestFinishedOf`, and `isSlotFinishedBy` takes either busy slot. `materializeStocks` splits every span at each season boundary it crosses, the epoch included (`nextSeasonBoundaryAfter` in `season/`), and accrues each segment with `accrue` at `deriveResourceRates` for the segment's start: k boundaries make k + 1 segments, each floored and clamped on its own, so a read may land up to one unit per boundary below the unfloored sum. A finish and a boundary order themselves by instant, since each walk step is one more materialization. The walk stops at the first upgrade still building; with nothing left the slot is idle. It accrues to `now`, or to the fief's `storedAt` when that is later. `hasChanged` is true when the read restarted the queue or completed at least one upgrade or study. `ResolvedFief` is `ChangedFief & { hasChanged }`: one event per finish the walk applied, in walk order (upgrade first on a tie), each at its `finishesAt`, never `now`; `events: []` when `hasChanged` is false, and no event for the entries `resumeBuildQueue` drops.
- `BuildingKind` has six members; `library` levels are a `LibraryLevel` (cost, duration, occupancy, no effect), so every `FiefBuildingLevels` fixture carries a `library` key.
- `Fief` carries `studySlot` (`StudySlot`, idle on `found`): idle, or busy with `art`, `targetLevel`, `startedAt`, `finishesAt` and the `cost` it debited, mirroring the busy `BuildSlot`. `Fief.restore` refuses a busy study whose target level is below 1 (`InvalidArtLevel`), that finishes before `storedAt`, that starts after it finishes, or that holds a negative cost, with the same members as the build slot (`validateTimedWork`). Every `StoredFief` fixture carries a `studySlot` key.
- Known gap: neither `Fief.restore` nor `completeStudy` checks a study's `targetLevel` against the current art level or the catalog; a stored study that targets a level the catalog lacks makes every read after its finish fail with `UnknownArtLevel`, like the building gap above.
- `Fief.startStudy(line, stocksAtNow, now, studyPercent)` is the only way a study starts. It refuses `StudySlotBusy` (a study runs), then `LibraryLevelTooLow` (the built `library` level is below the line's `requiredLibraryLevel`, level 0 included), then `InsufficientResources`. It debits the line's cost at `now` and touches neither the build slot, the build queue nor the peasants. The use case `startStudy` reads `nextArtLevelOf(art, level, catalog)` first and answers `ArtMaxLevelReached` when there is no next line. `deriveStudyDurationSeconds(durationSeconds, libraryLevel, studyPercent)` is `ceil(durationSeconds * studyPercent / (100 * (1 + libraryLevel)))` at the built library level, never the projected one: one division and one `ceil`, never a rounding per factor (1000 s at library 2 in a 75 % winter is 250, where two roundings give 251). The use case hands `Fief.startStudy` the study percent of `durationPercentAt(now, settings)`, so the `Fief` reads no calendar; the overview reads the same function at `storedAt`. `deriveBuildDurationSeconds(durationSeconds, buildPercent)` is `ceil(durationSeconds * buildPercent / 100)`; `enqueueBuilding` stores it on the entry with the build percent at `now`, whether the entry takes the slot or waits, and nothing retimes a stored entry or a running study when the season turns (ADR 011). A positive duration never scales below 1 second; a duration of 0 stays 0. `artLevelInForce(art, level, catalog)` answers the line in force (`undefined` at level 0, `UnknownArtLevel` for a missing or mismatched line), read by `deriveResourceRates` and the overview. `artResourceOf(art, catalog)` answers the resource the art's level-1 line raises (`UnknownArtLevel` with `level: 1` when that line is missing or mismatched), read by the overview; both share the guard in `artLineOf`.
- `Fief.cancelStudy(target, stocksAtNow, now)` is the only study cancel. It and the `cancelStudy` use case answer a `ChangedFief` with one `studyCancelled` refunding the study slot's stored cost at the cancel instant. `target` is a `StudyTarget` (`art`, `targetLevel`). It refuses `StudyNotFound` when the study slot is idle, holds another art or level, or has finished by `now` (`isSlotFinishedBy`). It credits the slot's stored `cost` to `stocksAtNow`, even above the capacity, stamps `storedAt = now` and idles the study slot; no cascade, and the build slot, the build queue and the art levels are untouched. The use case `cancelStudy({ playerId, art, targetLevel })` materializes the stocks at `now` first.
- Known gap: `cancelUpgrade`, `enqueueBuilding`, `startStudy` and `cancelStudy` open the same way (load the fief, `FiefNotFound`, `materializeStocks` at `now`, mutate, save), four copies awaiting one shared opening.
- `FiefEvent` (`fief/FiefEvent.ts`) is a union on `kind`: `upgradeFinished` (`building`, `level`, `occurredAt`), `artLearned` (`art`, `level`, `occurredAt`), `upgradeCancelled` and `studyCancelled` (the same plus `refund`, a `Stocks`). `level` is the level reached or the target level cancelled. A refused call answers an error and no event. `ChronicleWriter` (`ports/ChronicleWriter.ts`) receives them: `resolveUpgrade`, `cancelUpgrade` and `cancelStudy` take `chronicle` and call `record(fief.id, events)` right after `fiefs.save` succeeds, never when they save nothing. The domain never reads the chronicle. Tests pass `inMemoryChronicle()` (`testing/inMemoryChronicle.ts`, `recordedEventsOf(fiefId)`) or `refusingChronicle()`.
- `BuildingCatalog.artLevelOf(art, level)` answers an `ArtLevel` (`art`, `level`, `cost`, `durationSeconds`, `requiredLibraryLevel`, `resource`, `ratePercent`) or `undefined`. Every `BuildingCatalog` fake in the domain and api tests must implement it; `() => undefined` suffices where no art is studied.
- `Fief` carries `artLevels` (`FiefArtLevels`, with every `ArtKind` at 0 on `found`). `Fief.restore` refuses an art level that is negative or not whole with `InvalidArtLevel`. `artKinds` derives from a `Record<ArtKind, true>`, so a new art does not compile until it is listed.
- `deriveResourceRates(buildingLevels, artLevels, terrain, catalog, at)` sums base, producers and terrain. Then it collects the whole percents that scale each resource: `100 + ratePercent` of each art above level 0 on its line's `resource`, then, last, the percent of the season in force at `at` for every resource, so the season scales the terrain bonus and the arts too; before the epoch there is no season percent. Each rate is scaled once, as `rate * (product of its percents) / 100 ** count`: never `rate * (1 + ratePercent / 100)`, which falls short in floating point (200/h at 15 % would give 229.99…), and never one division per percent, which drifts too (31/h with a 5 % art in a 125 % season would give 40.68749…, not 40.6875). A missing or mismatched art line answers `UnknownArtLevel`. Level 0 reads no line. `materializeStocks` derives the rates anew at the start of each season segment (see the resolve gotcha).
- `FiefSettings.seasons` is a `SeasonCalendar` (`season/SeasonCalendar.ts`): `epoch` (an `Instant`), `daysPerSeason`, `multiplierPercent`, a whole percent per `SeasonKind` and resource, and `durationPercent`, a `DurationPercent` (`{ build, study }`, whole percents) per `SeasonKind`. `durationPercentAt(instant, settings)` (`season/durationPercentAt.ts`) answers the `DurationPercent` in force, `{ build: 100, study: 100 }` before the epoch; rates never read it and durations never read `multiplierPercent`. `seasonAt(instant, settings)` (`season/seasonAt.ts`) answers the `Season` in force (`kind`, `year`, `endsAt`) or `undefined` before the epoch: spring of year 1 starts at the epoch, the seasons run spring, summer, autumn, winter, and a season runs from its start, included, to its `endsAt`, excluded. Every `FiefSettings` fixture carries `seasons`; `testing/neutralSeasons.ts` is a calendar with every cell at 100, for tests that are not about seasons.
- Imports are extensionless (`'./Duration'`); the base tsconfig resolves as `Bundler` without `allowImportingTsExtensions`.
- `KingdomMapReader` (`ports/KingdomMapReader.ts`) is the map's read port: `addressOf(playerId)`, `lastOccupiedProvince(kingdom)` (0 when no fief), `holdersIn(kingdom, province)` answering `PlotHolder`s (`plot`, `name`, `playerId`). Its methods answer plain values, not a `Result`, like `FiefRepository.occupiedPlots`. Tests pass `inMemoryKingdomMap(heldPlots)` (`testing/inMemoryKingdomMap.ts`).
- `readProvinceMap({ playerId, province? }, { map, catalog })` answers a `ProvinceMap` (`kingdom/ProvinceMap.ts`). `lastProvince` is `lastOccupiedProvince + 1`, so the province past the last held one opens empty; a province below 1, not whole or above it refuses `ProvinceNotFound { province, lastProvince }`. Plots run 1..`plotsPerProvince`; a holder on a higher plot is not listed.
- `terrainOf(province)` takes the province number; the terrain belongs to the province, not the plot.
