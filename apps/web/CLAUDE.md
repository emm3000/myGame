# apps/web

TanStack Start on Vite: the routes, the design system and the game screens. It reads the api through `@mygame/contracts` only. Its copy comes only from `packages/catalog`, which holds the American English copy in `en.json` and the scaffold copy in `es.json`.

The rules: `.claude/rules/architecture.md`, `typescript-style.md`, `testing.md`, `ui-components.md`, `verification.md`. The code is the map: this file holds only the commands and the traps nothing else catches.

## Commands

- `WEB_PORT=<port> API_PORT=<port> pnpm --filter @mygame/web dev` — dev server on `WEB_PORT`. The port has no default and `strictPort` is on: an unset or busy port fails instead of drifting. `/api/*` is proxied to the api on `API_PORT` with the `/api` prefix stripped, so the session cookie is same-origin.
- `pnpm --filter @mygame/web test` — Vitest in happy-dom, `src/**/*.test.{ts,tsx}`, one DOM per test file.
- `pnpm --filter @mygame/web typecheck` — `tsc --noEmit`.
- `pnpm --filter @mygame/web drawables` — writes the Android VectorDrawable of every SVG under `public/art/places/` and `public/art/waste/` into `apps/android/core/designsystem/src/main/res/drawable/`. Run it after drawing or editing one; `src/art/townDrawables.test.ts` fails on a drift, a missing drawable or an orphan one.
- `pnpm --filter @mygame/web tokens` — writes `core:designsystem`'s Kotlin token files from `src/design/tokens.ts`. Run it after editing `tokens.ts`; `src/design/android/designSystemDriftsOf.test.ts` fails on a drifted value or a missing file.
- `pnpm --filter @mygame/web build` — production build through Nitro: `apps/web/.output/` outside Vercel, Vercel's Build Output in `.vercel/output/` at the repo root under `vercel build` (ADR 031). `WEB_PORT` and `API_PORT` are not read.
- `pnpm gate` from the repo root before every push.

## Gotchas

- `@mygame/catalog` exports no flat function: a test builds its expected text from the namespace the shown language picks, `es.x` or `en.x`. The stub player and town (`src/auth/stubApiClient.testSupport.ts`) default to scaffold `es` in the `scaffold` chrome phase, so a screen under test draws `es.json`'s lines unless the test sets the language.
- The api tests truncate the database that `DATABASE_URL` points at: run the gate before seeding a visual check, never between seeding and the screenshots.
- `src/routeTree.gen.ts` is generated by the Start plugin on `dev` and `build`, and committed so `typecheck` runs without a build. Never edit it by hand; after adding or renaming a route file, run one of the two and commit it.
- `nitro()` loads for `build` and `vite preview` only: in `dev` its middleware runs before Vite's proxy and answers `/api/*` with the router's 404 (#585).
- Tailwind's source detection skips what the root `.gitignore` names. `.output/` and `.vercel/` are listed there so the server build never scans the client build's files, emits a stylesheet with another hash, and links a `/assets/styles-*.css` that answers 404.
- The tokens replace Tailwind's default colors and spacing, so `bg-red-500` or `p-7` emit nothing and nothing fails.
- `src/design/tailwindTheme.ts` has a default export, the one exception to named exports only: Tailwind's `@plugin` reads `module.default ?? module` (ADR 009).
- Inside a `Block`, text takes `on-block` and `on-block-muted`, never `ink`, which flips in dark; `CountdownLine` takes `ground="block"` and a focus target `blockFocusTargetClass`, since `focus` in dark falls to 1.26:1 on mint.
- A pill (`Button`, `ButtonLink`) is `inline-flex`: it fills its column only as a direct child of a `flex-col`. A `flex` row or `items-start` around it shrinks it to its text.
- `vitest.setup.ts` fires `load` on each stylesheet link and each `as="style"` preload after it is inserted, because React 19 holds a commit until every head stylesheet has loaded. happy-dom loads no CSS file by default. `handleDisabledFileLoadingAsSuccess` in `vitest.config.ts` makes it fire `load` instead of `error` on a stylesheet link, but inside the insert itself, and never on a preload. Without the shim, a route test on real timers renders an empty document: 12 of the 29 files that call `renderAppAt` fail. The other 17 call `vi.useFakeTimers` and still pass, so a fake-timer route test proves nothing about the shim.
- `isolate` stays on: with one DOM shared across files, a component test's `render` into a `div` first sets React's listening marker on `document`, so a later `renderAppAt` registers no event listeners on `document` and every click in that route test is lost.
- A route test renders the real route tree with `renderAppAt(path, client)` (`src/auth/renderAppAt.testSupport.tsx`) over a stub `ApiClient`. `{ isStrict: true }` renders under `StrictMode`, the only way a test sees an effect run twice: use it for a post-once test.
- A double-click test fires both clicks in one `act` with a held promise: two separate clicks let React disable the button in between and never reach the in-flight guard.
- `formatQuantity` groups thousands with a narrow no-break space (U+202F). Testing Library's default normalizer turns it into a plain space, so a `getByText` expectation writes `1 200` and a `textContent` expectation `1 200`.
- Tests run in `Europe/Madrid`, set in `vitest.config.ts`: a clock or a day in an expectation is written in that zone.
- An inner `header` answers the `banner` role beside the shell's, and the shell's status line repeats a lesson's timer and link: a test takes the first `banner` and looks for a `timer` or a link shown twice inside `main`.

A PR adds a gotcha here only when it is a trap no code, rule or test catches, in one line, and never narrates its module.
