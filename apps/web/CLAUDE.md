# apps/web

TanStack Start on Vite: the routes, the design system and the game screens. It reads the api through `@mygame/contracts` only.

## Commands

- `WEB_PORT=<port> API_PORT=<port> pnpm --filter @mygame/web dev` — dev server on `WEB_PORT`. The port has no default and `strictPort` is on: an unset or busy port fails instead of drifting. `/api/*` is proxied to the api on `API_PORT` with the `/api` prefix stripped, so the session cookie is same-origin.
- `pnpm --filter @mygame/web test` — Vitest in jsdom, `src/**/*.test.{ts,tsx}`; `vitest.setup.ts` runs Testing Library cleanup after each test.
- `pnpm --filter @mygame/web typecheck` — `tsc --noEmit`.
- `pnpm --filter @mygame/web build` — production build into `dist/`.

## Layout

- `src/routes/` — TanStack file routes. `__root.tsx` owns the document and the head, and links `src/styles.css`.
- `src/routeTree.gen.ts` — generated by the Start plugin on `dev` and `build`; committed so `typecheck` runs without a build, excluded from Biome. Never edit it by hand.
- `src/router.tsx` — `getRouter`, the entry Start looks for.
- `src/design/tokens.ts` — the palette of the Design System artifact (issue #4), every colour under the artifact's name with its light (Parchment) and dark (Ledger) value, the type families, the spacing scale, the minimum heights (`min-h-control`, 44 px, every `Button` and `ButtonLink`; `min-h-plot`, 96 px, the `PlotTile`), the widths (`w-numeral`, 74 px, the `NumberField`) and the type scale. The only file allowed to hold a hex colour.
- `src/design/tailwindTheme.ts` — the Tailwind plugin built from `tokens.ts`: the `--<token>` variables per scheme and the theme (ADR 009). `src/styles.css` loads it with `@plugin`.
- `src/design-system/` — the hand-drawn SVG icons and the visual primitives (resource bar, building card, art card, countdown, build slot, panel, track), and `buildingArtOf`, the only file that knows the path of a building image under `public/art/buildings/` (tier = ceil(level / 2), none at level 0 or for a building whose `hasArt` is false, the library until S4 adds its art; the file-existence test covers only buildings that have art). Presentational only: props in, no api call, no timer. `BuildingCard` and `ArtCard` share `CostList`, `CardHeader` and `CardAction`; `CardAction`'s state is `affordable`, `blocked` with a reason (shown under the disabled button and appended to its accessible name), or `atMaxLevel` with a label, and it renders a primary `Button`. `SeasonLine` (the header's season line: the season icon in `ink-muted`, the header line in `numeral` and `ink`, a hidden middle dot, the countdown line in `ink-muted` with `role="timer"`; strings in, no calendar arithmetic, no ending tone) and the four season icons `SpringIcon`, `SummerIcon`, `AutumnIcon`, `WinterIcon` beside `ClockIcon`, `NoticeBanner` (line, one action, `aria-busy`, a sent or failed outcome), `MailIcon` (`IconFrame` takes `sizeClass`, default `size-4`), `ButtonLink` (a `Link` with `buttonClassOf(tone)`); `buttonClassOf` gives every button the 44 px minimum and a dashed `line` border when disabled. `AuthPanel`'s `onSubmit` and `footer` are optional: no `onSubmit`, no form.
- `src/copy.ts` — every Spanish string the player reads, addressed as tú (PRD N6). `copy.refusals` is keyed by `ApiErrorKind` plus `Unexpected`; the study refusals (`StudySlotBusy`, `LibraryLevelTooLow`, `ArtMaxLevelReached`, `StudyNotFound`) speak in the words of `docs/lore/arts.md`; `knownFief` in `stubApiClient.testSupport.ts` carries `study` (idle) and both `arts`; a screen shows a refusal by its kind, never by the api's `message`. A word next to a count agrees with the numeral right before it: 1 is singular, every other count, 0 included, is plural (`1 campesino libre`, `0 ocupados`); a single shortfall of 1 reads `Te falta`, anything else `Te faltan`. The count reaches the copy as a number, never a preformatted string. `names.arts` holds the art labels (*herrería*, *cantería*); `names.unstudied` (*sin estudiar*) is the level badge of an art at level 0; `names.studySlot`, `names.busyStudy` and `names.idleStudy` label the study slot. `names.seasons` holds the season labels (*primavera*, *verano*, *otoño*, *invierno*); `copy.fief.seasonLine(season, year)` reads *Otoño, año 1* and `copy.fief.seasonCountdown(nextSeason, remainingSeconds)` reads *Invierno en 3 días*: whole days, floored, while a day or more remains (*1 día*), the shared `formatDuration` under a day, which stays as every other countdown reads it. `copy.study` holds the section heading, *Estudiar*, *Cancelar el estudio*, `cancelOf(art, level)`, the effect line (`+N % de <resource> / h · nivel M: +P %`, or `· Ya está en su nivel más alto.` at the top level), the library requirement, and the running-study and library-too-low reasons.
- `src/api/apiClient.ts` — the `ApiClient` port and `createApiClient(baseUrl)`, the only file that calls `fetch`. It parses every body with a `@mygame/contracts` schema and turns an error body into its `ApiErrorKind`; anything else is `Unexpected`. `enqueueUpgrade(building)` posts `EnqueueBuildingRequest` to `/fief/upgrades` and answers the `FiefOverview` the route returns; `cancelUpgrade({ building, targetLevel })` sends `DELETE /fief/upgrades/<building>/<targetLevel>` and answers the same. `startStudy(art)` posts `StartStudyRequest` to `/fief/studies`; `cancelStudy({ art, targetLevel })` sends `DELETE /fief/studies/<art>/<targetLevel>`; both answer `FiefOverview`. `chronicle()` sends `GET /fief/events` and answers the `FiefChronicle` parsed by `FiefChronicleSchema`; the stub's default is `{ events: [] }`. `provinceMap(province?)` sends `GET /map` or `GET /map/<n>` and answers the `ProvinceMap` parsed by `ProvinceMapSchema`; the stub's default is `knownProvinceMap`: province 3 of 4, `ridges`, 15 plots, plot 12 the viewer's *Fuenteclara*. `verifyEmail(token)` posts `VerifyEmailRequest` to `/auth/verify-email` and `resendVerification()` posts to `/auth/verify-email/resend`; each answers `undefined` or its `ApiRefusal`; the stub answers `undefined` for both. `forgotPassword(email)` posts `ForgotPasswordRequest` to `/auth/forgot-password` and `resetPassword({ token, password })` posts `ResetPasswordRequest` to `/auth/reset-password`; each answers `undefined` or its `ApiRefusal`; the stub answers `undefined` for both.
- `src/routes/_signedIn.tsx`, `src/routes/_guest.tsx` — pathless layouts with `ssr: false` whose `beforeLoad` asks `currentPlayer()`: a signed-out visitor is sent to `/sign-in`, a signed-in one to `/`. The `ApiClient` reaches routes through the router context (`createRootRouteWithContext`), so tests pass a stub client to `createAppRouter` instead of mocking a module. `_signedIn`'s `beforeLoad` returns `{ player }` into the route context; the layout hands it to `AppShell` with `useResendVerification(apiClient)`.
- `src/auth/` — the sign-in and sign-up screens (presentational) and `renderAppAt`, which renders the real route tree at a path over a memory history for tests.
- `src/shell/` — the app shell: the title, the navigation (`copy.shell.navigation`: *Feudo* to `/`, *Mapa* to `/mapa`, *Crónica* to `/cronica`; each `Screen` carries `isExact`, and *Mapa* is not exact so it stays current on `/mapa/<n>`; TanStack `Link` sets `aria-current="page"`, and `activeProps` mark it with `font-bold`, `text-river` and a `border-b-3 border-river` underline), and *Salir* outside the `<nav>`. Because `Link` needs a router, a shell test renders through `renderAppAt`. `AppShell` takes `player` and `verification` and shows the banner at the top of `<main>` only while `emailVerified` is false.
- `src/map/` — the kingdom map at `/_signedIn/mapa/` and `/_signedIn/mapa/$province`. The numbered route parses the param with `ProvinceMapRequestSchema` and renders the `ProvinceNotFound` refusal without a request when the parse fails. The `ProvinceNotFound` state, from the parse or from the api, shows the refusal and a `TextLink` to `/mapa`, *Ir a tu provincia* (`copy.map.backToOwnProvince`). `useProvinceMap(apiClient, province)` reads on mount and on each province change, with no timer, and answers `loading | refused | read{map}`. `ProvinceMapPage` owns the hook and navigates to `/mapa/$province`. `MapScreen` is presentational: previous and next are disabled at 1 and at `lastProvince`, and the jump form sends only 1..`lastProvince`. `copy.map` holds the title, loading, `heading(kingdom, province)`, `terrain(terrain)`, `plot(n)`, *libre*, *Tu feudo* and the three controls; `names.terrains` holds *vega*, *páramo* and *riscos*. The route tests are in `mapRoute.test.tsx`. The header address of `src/fief/FiefScreen.tsx` is a `Link` to `/mapa/$province`.
- `src/verification/` — `useResendVerification` (`idle | sending | sent | refused`, one resend in flight, guarded by a ref), `VerificationBanner` (maps that state onto the design-system `NoticeBanner` with `copy.verification.banner`), `/verify-email` (`src/routes/verify-email.tsx`, outside both layouts, `ssr: false`, `validateSearch` parses `token` with `VerifyEmailRequestSchema`), `useVerifyEmail` (posts once on mount, a ref guards the development double mount; a missing token is `TokenInvalid` with no request) and `VerifyEmailScreen` (presentational, `AuthPanel` frame). Route tests: `verificationBannerRoute.test.tsx`, `verifyEmailRoute.test.tsx`.
- `src/passwordReset/` — `ForgotPasswordScreen` (presentational; `editing | sending | sent`; checks the email with `ForgotPasswordRequestSchema` and shows `copy.auth.invalidEmail` with no request; `sent` replaces the form with the one confirmation line) behind `/forgot-password` (`routes/_guest/forgot-password.tsx`, under `_guest`), and `ResetPasswordScreen` (presentational; `editing | sending | changed | linkRefused`) behind `/reset-password` (`routes/reset-password.tsx`, outside both layouts so it works signed in or out, `ssr: false`, `validateSearch` parses `token` with `ResetPasswordRequestSchema.shape.token`; the route checks the password with `ResetPasswordRequestSchema` and shows `WeakPassword` with no request; `TokenInvalid` or a missing token is `linkRefused`, with *Pedir otro enlace* to `/forgot-password`). `copy.passwordReset` holds `request` and `newPassword`; `copy.auth.signIn.forgotPassword` is the sign-in link. Route tests: `forgotPasswordRoute.test.tsx`, `resetPasswordRoute.test.tsx`.
- `src/chronicle/` — the chronicle at `/_signedIn/cronica`: `useChronicle` (reads once on mount, answers `loading | refused | read{chronicle, readAt}`; no re-read, no timer; returning to `/cronica` reads again), `ChronicleScreen` (presentational), `chronicleRowOf` (the sentence heading by `kind`, the label and level, the refund as the lore sentence plus `CostList` entries in the Resources order, zero amounts dropped), and `formatInstant(instant, now)` (browser time zone: `Hoy, HH:MM`, `D mmm, HH:MM`, `D mmm YYYY, HH:MM`, with the month from `Intl.DateTimeFormat('es', { month: 'short' })`). `copy.chronicle` holds the title, loading, empty line, headings, `subject(label, level)`, *Recuperas* and `refunded(quantities)`. The route tests are in `chronicleRoute.test.tsx`.
- `src/fief/` — the fief screen at `/_signedIn/`: `FiefScreen` (presentational; one design-system `BuildingCard` per building), `buildingCardOf` (a card's costs and state from the building's `nextLevel` against the interpolated amounts and `peasants.projectedFree`, the free peasants left after every waiting upgrade, in the artifact's precedence: at max level, then `blocked` with the first reason that applies (queue full: the slot busy and `queue.entries` at `queue.cap`, with `copy.refusals.QueueFull` as the reason; not enough peasants; too expensive), else affordable; `resourceCostsOf` and `shortfallsOf` hold the cost and shortfall logic both card builders use), `liveFief` (interpolation from the last `FiefOverview` and its rates, up to the capacity; an amount already above the capacity freezes where the read left it; the slot countdown; the track total, the busy slot's `finishesAt - startedAt` in seconds, so the track is exact after a reload; `waitingUpgrades`, each queue entry's countdown to its `finishesAt` from the overview alone), the design-system `WaitingUpgrades` list under the slot, the resource bar's peasant cell showing the projected trio (`projectedFree` / `projectedSupplied`, `projectedOccupied`), so its free figure is the one the cards check and never exceeds its supply, `useLiveFief` (the re-read policy: on mount, on window focus, when the slot countdown reaches zero, and 60 seconds after the last read; `adopt` takes an overview answered by another call as a read) and `useFiefAction` (the policy every fief action runs under, one instance per caller: one action of that caller in flight at a time, guarded by a ref so a double click never sends twice, every button of that action disabled meanwhile; success adopts the answered overview; a refusal, carried with the action's subject, shows until the next read arrives; an upgrade and a cancel hold separate instances, so they can be in flight together). `useUpgrade` runs the enqueue under it and shows its refusal under the refused card; `useCancel` runs the cancel buttons under it, one on the busy slot and one on each `WaitingUpgrades` row, each naming its entry and carrying `copy.fief.cancelOf(building, level)` as its accessible name, with its refusal under the slot; the `justFinished` slot has no button. Its route tests live here as `fiefRoute.test.tsx`, `fiefUpgradeRoute.test.tsx` and `fiefCancelRoute.test.tsx`, on fake timers. `LibrarySection` appears under the buildings once `buildings.library.level >= 1`: the study slot, a `BuildSlot` titled *el estudio* when idle or just finished and *un estudio en marcha* when busy, with a cancel button named `copy.study.cancelOf(art, level)`, plus one `ArtCard` per art from `artCardOf`, whose effect icon is `overview.arts[art].resource`, which shows effect, cost, duration and the library requirement (in rust when unmet) and checks the reasons in this order: at max level, a study running, library too low, resources short. `liveFief` also carries the study countdown and track total; `useLiveFief` also re-reads when the study countdown reaches zero. The header shows the season line under the fief name for a non-null `overview.season` and nothing of the season for `season: null`; the next season's label comes from the fixed order in `FiefScreen` (after winter, spring), the rest from the overview. `liveFief` carries `seasonRemainingSeconds`, the seconds from `readAt` to `season.endsAt` (0 when `season` is null), and `useLiveFief` re-reads when they reach zero; every re-read `setTimeout` is clamped to 2^31 - 1 ms, past which it would fire at once, and an early read only reschedules. The route tests are in `fiefSeasonRoute.test.tsx`. `useStudy` runs `start(art)` and `cancel(target)` under one `useFiefAction`, so every study and cancel button is disabled while one runs, and shows its refusal under the section. The route tests are in `fiefStudyRoute.test.tsx`.

## Gotchas

- No raw `fetch` with an ad-hoc shape. A call to the api is typed by a schema from `@mygame/contracts`.
- The design system is the only source of visual primitives: style with the Tailwind utilities the theme derives from `tokens.ts` (`bg-surface`, `p-4`, `text-body`), never a hex, a px literal or a `style` prop. Arbitrary values (`p-[13px]`) fail `biome check`. A missing value goes into `tokens.ts`. Check: `rg -n "#[0-9a-fA-F]{6}" apps/web/src --glob '!**/tokens*'` stays empty.
- No Spanish outside `copy.ts`; identifiers stay English.
- `copy.refusals` includes `TokenInvalid` and `MailNotSent`, the same lines as the api's `answerRefusal.ts`; `knownPlayer` in `stubApiClient.testSupport.ts` carries `emailVerified: true`.
- React 19 holds a commit until every head stylesheet fires `load`, which jsdom never does, so the root document rendered empty in tests. `vitest.setup.ts` dispatches `load` on each stylesheet or style preload link as it is inserted.
- No snapshot tests. Components are tested through Testing Library queries by role and text; visual verification is a screenshot in the PR.
- `renderAppAt(path, client, { isStrict: true })` renders under `StrictMode`, the only way a test sees an effect run twice; use it for a post-once test. A double-click test fires both clicks in one `act` with a held promise; two separate clicks let React disable the button in between and never reach the in-flight guard.
- Testing Library's default normalizer turns the thin space from `formatQuantity` into a plain space, so a `getByText` expectation writes `1 200` with a plain space.
- The api tests truncate the database that `DATABASE_URL` points at, so run `pnpm gate` before seeding a visual check, never between seeding and the screenshots.
- Tailwind's default colours and spacing multiplier are replaced by the tokens, so `bg-red-500` or `p-5` emit nothing; breakpoints stay Tailwind's defaults.
- `src/design/tailwindTheme.ts` has a default export, the single exception to "named exports only": Tailwind's `@plugin` reads `module.default ?? module` and needs the plugin object there (ADR 009).
- `tailwindcss()` is the first Vite plugin, before `tanstackStart()`.
- pnpm refuses packages younger than its minimum release age. Pin the newest version old enough instead of adding a `minimumReleaseAgeExclude` entry.
