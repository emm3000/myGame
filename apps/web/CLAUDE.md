# apps/web

TanStack Start on Vite: the routes, the design system and the game screens. It reads the api through `@mygame/contracts` only.

## Commands

- `WEB_PORT=<port> API_PORT=<port> pnpm --filter @mygame/web dev` — dev server on `WEB_PORT`. The port has no default and `strictPort` is on: an unset or busy port fails instead of drifting. `/api/*` is proxied to the api on `API_PORT` with the `/api` prefix stripped, so the session cookie is same-origin.
- `pnpm --filter @mygame/web test` — Vitest in jsdom, `src/**/*.test.{ts,tsx}`; `vitest.setup.ts` runs Testing Library cleanup after each test.
- `pnpm --filter @mygame/web typecheck` — `tsc --noEmit`.
- `pnpm --filter @mygame/web drawables` — cuts every SVG under `public/art/places/` at levels 0 to 10 and converts `public/art/waste/` into their Android VectorDrawables in `apps/android/core/designsystem/src/main/res/drawable/` (`src/art/generateDrawables.ts`, through `tsx`). Run it after drawing or editing one of those SVGs; `src/art/townDrawables.test.ts` fails on a drift, a missing drawable or an orphan one.
- `pnpm --filter @mygame/web tokens` — writes `core:designsystem`'s `MyGameColors.kt`, `MyGameTypography.kt`, `MyGameTypeFamilies.kt`, `MyGameSpacing.kt`, `MyGameRadii.kt`, `MyGameSizes.kt`, `MyGameStrokeWidths.kt` and `MyGameTransitions.kt` in `apps/android/core/designsystem/src/main/kotlin/com/emm/mygame/core/designsystem/` from `src/design/tokens.ts` (`src/design/android/generateDesignSystem.ts`, through `tsx`). Run it after editing `tokens.ts`; `src/design/android/designSystemDriftsOf.test.ts` fails on a drifted value or a missing file.
- `pnpm --filter @mygame/web build` — production build through Nitro (`nitro()` from `nitro/vite`, after `tanstackStart()`, loaded for `build` and `vite preview` only: in `dev` its middleware runs before Vite's proxy and answers `/api/*` with the router's 404, #585): outside Vercel it writes `apps/web/.output/`; under `vercel build` it writes Vercel's Build Output to `.vercel/output/` at the repo root, the static files (`assets/` with hashed names, `art/` from `public/`) and one `__server` function (ADR 031). `WEB_PORT` and `API_PORT` are not read.
- `apps/web/vercel.json` — production on Vercel: `/api/:path*` rewritten to the api project's domain with the prefix stripped, so the session cookie stays same-origin as in `dev`; a one-year `immutable` `cache-control` on `/assets/` and a one-day one on `/art/` (unhashed, from `public/`); region `iad1`; Git deploys off, since `deploy.yml` deploys.

## Layout

- `src/routes/` — TanStack file routes. `__root.tsx` owns the document and the head, and links `src/styles.css`.
- `src/routeTree.gen.ts` — generated by the Start plugin on `dev` and `build`; committed so `typecheck` runs without a build, excluded from Biome. Never edit it by hand.
- `src/router.tsx` — `getRouter`, the entry Start looks for.
- `src/design/tokens.ts` — the look (ADR 043), the source of every value: the 20 colors with their light and dark values, the four `block-*`, `on-block` and `on-block-muted` one value in both themes; the one family `sans`, Schibsted Grotesk, loaded from Google Fonts by `__root.tsx` as `Schibsted+Grotesk:wght@400..800`, no italics; the 12 type styles of ADR 043's table (`word`, `display`, `numeral`, `reading`, `heading`, `button`, `title`, `gloss`, `body`, `label`, `caption`, `meta`; unitless line heights), where `word` carries a second size in `fontSizeFromMd` (44 px, 52 px from `md`), `numeral` alone carries `fontVariantNumeric: 'tabular-nums'` (a figure in `caption` takes `tabular-nums` on its own element, since `tnum` widens the punctuation of prose), and `meta`, the only uppercase style, carries `textTransform`; the spacing scale; the minimum heights `min-h-action` 60 px, `min-h-secondary` 52 px and `min-h-control` 48 px; the sizes (`size-icon` 24 px, `size-icon-small` 20 px, `size-thumbnail` 96 px, `size-place-card` 160 px); the maximum widths (`max-w-form` 640 px, `max-w-reading` 65ch, under the theme's `extend`); `h-track`, 3 px; the radii (`rounded-sm` 8 px, `rounded-md` 16 px, `rounded-lg` 28 px, `rounded-pill`); no shadow, a `line` hairline in its place; the stroke widths (`hairline` 1, `control` 2, `icon` 2, which `IconFrame` reads, `mark` 2, `focus` 3, `ring` 4, which `RetainedWordsRing` reads; no Tailwind utility); the durations and easings, and `transitions.track` built from them (`width 320ms` on `easings.standard`, the utility `transition-track`, which `Track` alone applies and only under `motion-safe:`). `min-h-plot` (96 px), `w-numeral` (74 px) and `w-control` (48 px) are still defined and no screen uses them. The breakpoints (`md` 48rem, `lg` 64rem, under the theme's `extend`) and the scroll margin (`scroll-mt-status`, `calc(var(--status-block-height) + 1px)`, the property `statusBlockHeightProperty` names, #506) are layout constants. `src/design/tokens.test.ts` declares ADR 043's 29 pairs in both themes, each `text` at 4.5:1 and `boundary` at 3:1 (WCAG 2.2 AA, N8), and its four exemptions, three under WCAG 1.4.11 (`line` on a surface, a block on `surface`, a silhouette on `surface`) and one under 1.4.3 (the disabled `line-strong` label on `surface-sunken`); an exempt pair fails once it passes on its own. A new color pair is declared there. Hex colors live here and, as SVG fixtures, in the tests under `src/art/`.
- `src/design/tailwindTheme.ts` — the Tailwind plugin built from `tokens.ts`: the `--<token>` color variables per scheme, the theme (`h-track` under its `extend`), one `.transition-<token>` utility per transition token (ADR 009, ADR 029), and one `.text-<style>` utility for what a font-size tuple cannot hold: `word`'s size from `md`, `meta`'s uppercase and `numeral`'s tabular figures. No color is named like a type style, so `text-gloss` sets the type style. `src/styles.css` loads it with `@plugin`.
- `src/design-system/` — the hand-drawn SVG icons and the visual primitives (countdown, build slot, panel, track). `placeArtOf(place, level)` is the only file that knows a town place's image: it inlines `public/art/places/<place>.svg` through a `?raw` import and answers the shapes to draw, the silhouette in `surface-sunken` at level 0, and from level 1 the file's own hue with the first `level` windows; `placeSilhouetteOf(place, token)` answers the silhouette alone in a token. `wasteArtOf(size)` is the only file that knows a waste site's image: it inlines `public/art/waste/waste-<size>.svg` through a `?raw` import and answers its shapes in `ink-muted` (ADR 043), for `PlaceArt` to draw; `WasteSize` is the size the wire's `RegionMap` site carries, 1 to 3. `PlaceArt` draws those shapes in a `size-place-card` square, the `0 0 100 142` frame letterboxed inside it; only Android sizes its width from the frame. `blockHueOf(index)` answers the hue of an index, and `hueClassOf(hue)` its class. `resourceAccent` keys the town's resources (`money`, `food`, `power`, `material`, with `MoneyIcon`, `FoodIcon`, `PowerIcon` and `MaterialIcon`) and `people` (`PeopleIcon`); each is a hand-drawn stroke icon, never a raster image (ADR 030 amendment, #580), taking `sizeClass` as `IconFrame` does, and every use of `resourceAccent` (`CostList`, `TownStocks`, `SkillList`) draws it. Presentational only: props in, no api call, no timer. `Panel`, the frame of `AuthPanel` and `NameTownScreen`, draws `rounded-md border`, and its `toneClass` names the border color and the ground (ADR 043). `BuildSlot`'s idle frame is a solid `line` border on `surface-raised`. `on-action` on `action` serves the primary `Button`. A `CardCost` carries its `spokenName` and its `shortMark` (S25, #524): each line reads the figure, then a visually hidden name (`town.costName`, *de material*), then, while short, a visually hidden `town.shortMark`, *, falta*, so a screen reader hears *60 de material, falta* and the short line is never told by `warning-ink` alone; the icon stays `aria-hidden`. `CancelRow` (#524) draws every cancel of the build slot, the waiting list and the lesson slot: a `flex-wrap` row after a `line` hairline, the refund line first in `caption` `ink-muted`, then the quiet `Button` at its natural width, right-aligned by `justify-end`; the line is outside the button, whose accessible name stays its `aria-label`. `LiveRegion` is the visually hidden `aria-live="polite"` region; it carries no `role`, since `status` would collide with `NoticeBanner` in tests that query that role, and its tests find it by the attribute. `CardAction` (S22, #472, #981) is the one action of every place card, `type` `button`: its state is `affordable`, `blocked` with a reason and an optional `ready` line, `invalidEntry` with a reason, or `atMaxLevel` with a label, and it renders a `Button` of its `tone`, `primary` unless a caller passes another (`PlaceRow` passes `quiet`). `blocked` marks either the client's own arithmetic (a shortfall, people short, a busy slot or list) or the server's verdict on a quote (a refused quote on the map's forms), and in both cases still calls `onAction`, since the api's answer to the send is the only verdict and is drawn inline (`.claude/rules/android-architecture.md`, The client never decides); while that request is in flight it waits like any other. `invalidEntry` is an entry that builds no request (a count that is not whole, an empty team, the hours) and asks nothing. A blocked, waiting or max-level button is never `disabled`: it stays in the tab order and draws with a dashed `line-strong` border on `surface-sunken` with `ink-muted` text. `Button`'s `availability` `blocked` (an `invalidEntry` or a max-level button) and `waiting` set `aria-disabled="true"` and swallow its click (and so Enter, Space and a form's submit through it); `marked`, which a `blocked` `CardAction` passes, keeps the same look with `cursor-pointer`, carries no `aria-disabled`, since it still acts, and fires `onClick`. `announcesReason`, which the job and clean-up forms pass, keeps an `aria-live="polite"` region mounted, empty and `empty:absolute` so it stays in the accessibility tree, and announces there only a `blocked` reason, the server's refused quote; an `invalidEntry` reason, which changes with every keystroke, stays the button's description in a plain line (waiting: a solid border, `aria-busy`, `cursor-progress` and the `ClockIcon` before the label; `waitingInPlace`, which `CardAction` takes from `keepsLabelWidth` and only `PlaceRow` passes, draws the same pill with `px-2`, `gap-1` and a `size-icon-small` clock: 16 px of padding, a 20 px clock and a 4 px gap add up to the 40 px of `px-5`, so the label keeps its idle width and the pill its idle height, #891). The reason reads beside it in `caption` `warning-ink`, followed by the `ready` line in semibold `caption` `ink`, and the button's `aria-describedby` names that line, so the reason and *lista* are its accessible description; its accessible name stays the label. Tests read the description with `accessibleDescriptionOf` (`accessibleDescriptionOf.testSupport.ts`) or `getByRole('button', { name, description })`. `SeasonLine` (the season line: the season icon in `ink-muted`, the line in `caption` and `ink`, the countdown line in `ink-muted` with `role="timer"`, behind a hidden middle dot that sits in the gap, so a wrapped line clips it; strings in, no calendar arithmetic, no ending tone), `seasonIconOf` (the season-to-icon map `SeasonLine` shares), and the four season icons `SpringIcon`, `SummerIcon`, `FallIcon`, `WinterIcon` beside `ClockIcon`, `NoticeBanner` (one `sticky bottom-0` line on `surface` over a `line` top border: the line in `caption` `ink-muted`, swapped for a sent outcome in `ink` with `role="status"` or a failed one in `destructive-ink` with `role="alert"`, beside a `text` `Button`; `aria-busy`), `BackIcon` (`IconFrame` takes `sizeClass`, default `size-4`, and draws at `strokeWidths.icon`, 2; `SlotIcon` and `ClockIcon` pass an optional `sizeClass` through), `TextField` (a labelled input at `min-h-control`, with an optional `lang`; `isDisabled` draws it with a dashed `line-strong` border on `surface-sunken` with `ink-muted` text and `cursor-not-allowed`, as a disabled button), `SlotHeading` (the icon and the label every slot opens with), `CountdownLine` (the `role="timer"` line the slots draw), `Track` (`h-track`, 3 px; an optional `marks`, values on the same scale as `value`, each a 2-unit `line-strong` rect; the fill `rect` carries `motion-safe:transition-track`, the one transition of the app, which reaches the `width` attribute as an SVG 2 geometry property, measured in headless Chromium only) and `ButtonLink` (`createLink` over an anchor with `buttonClassOf(tone)`, so a path with `$` segments takes its `params`; it centres its label). `ButtonTone` is `primary`, `quiet` or `text`, and a text button has a transparent border and ground and underlined `ink` text at `min-h-control`; `TextLink` is `inline-flex` at `min-h-control`, as ADR 043 asks of the back link, every text link and every text button; `Button` takes an optional `isExpanded` for `aria-expanded` and an optional `controls` for `aria-controls`; `buttonClassOf` gives each tone its height, `primary` 60 px, `quiet` 52 px and `text` 48 px, and a dashed `line` border with `ink-muted` text when `disabled`, which the banner's action and the submit buttons of the sign-in, sign-up, forgot-password and reset-password forms still set while they send; a cancel waits with `availability="waiting"`, never `disabled`, so it keeps focus (#493). `AuthPanel`'s `onSubmit` and `footer` are optional: no `onSubmit`, no form; its `h1` keeps `text-display`. It draws no scene band: the panel opens the screen, and the game's title (`shell.title`) inside the panel above the `h1`, so no text sits on the band.
- The block and the pill (ADR 043, #865): `Block` (`src/design-system/Block.tsx`) is a flat `section` of radius `lg`, `on-block` text on one of the four hues (`hue`, exposed as `data-hue`), with no border and no pill inside. The primary action is `Button` or `ButtonLink` with `tone="primary"`, the one filled control on a screen: an ink pill at `min-h-action`, in `text-button`, set under the block on paper so its boundary and focus ring are measured on a surface. Every other action is `tone="quiet"`, an outlined pill at `min-h-secondary` in `text-label`, or `tone="text"` at `min-h-control`. Inside a block, text uses `on-block` and `on-block-muted`, never `ink`, which flips in dark: `CountdownLine` takes `ground="block"` there.
- `src/art/` — the town's illustrations as files, not screens (#758, #863, `docs/art/art-bible.md`, Model and size): `artProblemsOf(svg, family)` lists every way an SVG breaks the bible, its `ArtFamily` (`places` or `waste`, the directory under `public/art/`) choosing the family's rules: for both, a `viewBox` other than `placeViewBox`, an element other than `rect`, `circle` and `polygon` under the root `svg`, so no `path`, whose curves `artFramingOf` could not measure, an attribute outside each element's list, so no `stroke`, `transform`, `style` or `opacity`, a missing fill, a fill off the four blocks and `on-block`, no silhouette, more than 12 KB; for a place, a silhouette of more than one hue or off the blocks, a window not in `on-block`; for a waste file, which has no windows, more than one fill; `artPalette` derives those fills from `palette` and holds no hex; `placeShapesOf(svg)` splits a file into its silhouette and its ten windows, and `placeAtLevelOf` cuts a file at a level; `artFramingOf(svg, family)` measures the silhouette (every shape of a waste file): its bounding box as shares of the frame, its base line, the share of the frame it covers, sampled every 2 units, the windows off it and the windows that overlap an earlier one; Its paths come from `import.meta.dirname`, since jsdom gives `import.meta.url` no `file:` scheme. The town home and the word card read the place files through `placeArtOf` and `wordArtOf`. `biome.json` leaves `public/art` out: Biome lints an SVG as markup and asks for a `<title>`, but the art is inlined with `aria-hidden` beside the text that names it, and `artProblemsOf` is the check these files answer to.
- `@mygame/catalog` (`packages/catalog/es.json`) — the only source of copy: every Spanish string the player reads, addressed as tú (PRD N6), one generated function per key (`town.loading` is `townLoading()`, `town.level` is `townLevel({ level })`); after an `es.json` edit, `pnpm --filter @mygame/catalog generate`. Logic that is not a string stays in the web, in modules named for what they do: the lookups from a kind to its `names.*` key (`townResourceNameOf`, `seasonNameOf`, `placeNameOf`), `conjunctionOf` and `refusalLineOf`. `refusalLineOf(refusal, error)` (`src/refusals/`) is the one reading of a refusal, from one `refusal.<Kind>` key per `ApiErrorKind` plus `refusal.Unexpected`, and it is exhaustive: a `Record` of the lines with no fields and a `switch` over the kinds with `params` that ends on `never`, so a new kind fails the typecheck. A screen shows a refusal by its kind; the api sends no line (ADR 038, #736). The kinds with fields (`WaitingListFull`, `NotEnoughPeople`, `NotEnoughResources`, `TopLevelReached`, `BuildingWorkNotFound`, `LearningCapReached`) arrive with their `params` and `refusalLineOf` renders each from them through its key; one handed to `refusalLineOf` without its `error` reads `refusal.Unexpected`. The `ApiOutcome` refusal carries the parsed `ApiError` as `error`. A word next to a count agrees with the numeral right before it, through an ICU plural in its key (`{count, plural, =1 {...} other {...}}`): 1 is singular, every other count, 0 included, is plural (`1 libre`, `0 libres`). The count reaches the key as a number, never a preformatted string. `names.seasons.*` hold the season labels (*primavera*, *verano*, *otoño*, *invierno*); `town.season.line` reads *Otoño, año 1* and `town.season.endsIn` the countdown to the next season, *Invierno termina en 3 días*, in whole days, floored, while a day or more remains (`town.season.days`), `formatTimeLeft` under a day.
- `src/api/apiClient.ts` — the `ApiClient` port and `createApiClient(baseUrl)`, the only file that calls `fetch`. `regionMap(area?)` sends `GET /town/map`, or `/town/map/<area>`, and answers the `RegionMap`, `AreaNotFound` past the last browsable area; `quoteJob(job)` posts `SendJob` to `/town/jobs/quote` and answers the `JobQuote` (#958); `sendJob(job)` posts `SendJob` to `/town/jobs` and `callJobBack({ sentAt })` posts to `/town/jobs/<sentAt>/call-back`, the instant URI-encoded, each answering the `TownOverview` (#783); `quoteCleanUp(cleanUp)` posts `SendCleanUp` to `/town/clean-ups/quote` and answers the `CleanUpQuote` (`strength`, `waste`, `pay`, `covers`), and `sendCleanUp(cleanUp)` posts it to `/town/clean-ups` and answers the `TownOverview` (#787) (tests in `apiClient.test.ts`, over a stubbed global `fetch`). `verifyEmail(token)` posts `VerifyEmailRequest` to `/auth/verify-email` and `resendVerification()` posts to `/auth/verify-email/resend`; The learning calls are the player's: `reviews()` sends `GET /reviews` and answers the `Reviews` (`due`, `nextDueAt`, `readAt`), the stub's default none due and `nextDueAt: null`; `reviewHint(wordId)` posts to `/reviews/<wordId>/hint` and answers the `ReviewHint`; `answerReview({ wordId, answer })` posts `ReviewAnswerRequest` to `/reviews/<wordId>/answer` and answers the `ReviewAnswer`, its `verdict` alone. `startLesson(lessonId)` posts `StartLessonRequest` to `/town/lessons` and `stopLesson(lessonId)` sends `DELETE /town/lessons/<lessonId>`, each answering the `TownOverview` (#770). `report()` sends `GET /report` and answers the `Report` (`dueCount`, `due`, `news`), the stub's default none due and no news; `closeReport()` posts to `/report/close` and answers `undefined` or its `ApiRefusal`, the stub `undefined` (#773).

- `src/review/` — the review at `/reviews` (`routes/_signedIn/reviews.tsx`, #714, ADR 036, #773, ADR 041; the lines in the `review.*` keys). It reads the player's reviews (#769, ADR 040): `useReviews(apiClient)` reads `reviews()` on mount and answers `loading | refused | read{reviews, at}` with a `reread` that keeps the shown read until its answer, `at` the reviews' `readAt` plus the time since the answer arrived, repainted once a minute; loading reads *Estamos leyendo tu repaso…* and a refused read *No hemos podido leer tu repaso.* with *Volver a intentarlo*, which calls that `reread`. `useReview(apiClient, due, reread)` shows `due[0]` and holds it from the first touch (a choice, a keystroke, the hint, the check) until *Siguiente*, with the due count *Por repasar* read at that touch, so a re-read never swaps the card under the player and never reads 0 under the last card; the recall field caps at `ReviewAnswerRequestSchema`'s `maxLength` and *Comprobar* is blocked while it is empty, and `useReview` sends no empty recall, so Enter in the empty field sends nothing either; the answer posts once (a ref guards it) with `answerReview({ wordId, answer })`, the typed text exactly as typed or the recognition's `choiceId`, then re-reads the reviews before it shows the verdict, so *Siguiente* reads the next card from the re-read. With no card shown it reads *Aún no tienes palabras que repasar.* while `nextDueAt` is null, else *No tienes nada que repasar ahora.* and *Siguiente repaso:* `nextDueAt` through `formatFinish` at that `at`, and offers no practice; with nothing due, `useReviews` re-reads the reviews `nextDueAt - readAt` after the answer, so the server's read instant paces it. The English word, frame and gapped frame carry `lang="en"`, every gloss `lang="es"`. Route tests: `reviewRoute.test.tsx`. No *Repaso* entry in the navigation: the Report's *Empezar los repasos* and the town home's next step link to it.

## Gotchas

- No raw `fetch` with an ad-hoc shape. A call to the api is typed by a schema from `@mygame/contracts`.
- The design system is the only source of visual primitives: style with the Tailwind utilities the theme derives from `tokens.ts` (`bg-surface`, `p-4`, `text-body`), never a hex, a px literal or a `style` prop. Arbitrary values (`p-[13px]`) fail `biome check`. A missing value goes into `tokens.ts`. Check: `rg -n "#[0-9a-fA-F]{6}" apps/web/src --glob '!**/tokens*' --glob '!**/art/**'` stays empty.
- No Spanish outside the catalog (`packages/catalog/es.json`); identifiers stay English.
- The catalog holds `refusal.TokenInvalid` and `refusal.MailNotSent`; `knownPlayer` in `stubApiClient.testSupport.ts` carries `emailVerified: true`.
- React 19 holds a commit until every head stylesheet fires `load`, which jsdom never does, so the root document rendered empty in tests. `vitest.setup.ts` dispatches `load` on each stylesheet or style preload link as it is inserted.
- No snapshot tests. Components are tested through Testing Library queries by role and text; visual verification is a screenshot in the PR.
- `renderAppAt(path, client, { isStrict: true })` renders under `StrictMode`, the only way a test sees an effect run twice; use it for a post-once test. A double-click test fires both clicks in one `act` with a held promise; two separate clicks let React disable the button in between and never reach the in-flight guard.
- `formatQuantity` groups thousands with a narrow no-break space (U+202F), so a figure never wraps; Testing Library's default normalizer turns it into a plain space, so a `getByText` expectation writes `1 200` with a plain space, while a `textContent` or array expectation writes `1\u202f200`.
- The api tests truncate the database that `DATABASE_URL` points at, so run `pnpm gate` before seeding a visual check, never between seeding and the screenshots.
- Tailwind's default colours and spacing multiplier are replaced by the tokens, so `bg-red-500` or `p-7` emit nothing; breakpoints stay Tailwind's defaults.
- `src/design/tailwindTheme.ts` has a default export, the single exception to "named exports only": Tailwind's `@plugin` reads `module.default ?? module` and needs the plugin object there (ADR 009).
- `tailwindcss()` is the first Vite plugin, before `tanstackStart()`.
- Tailwind's source detection skips what the root `.gitignore` names. Without it the server build scans the client files the client build just wrote, emits a stylesheet with another hash, and the SSR head links a `/assets/styles-*.css` that answers 404. `.output/` and `.vercel/` are in `.gitignore` for that reason.
- pnpm refuses packages younger than its minimum release age. Pin the newest version old enough instead of adding a `minimumReleaseAgeExclude` entry.
- `SignOutColumn` (`src/auth/SignOutColumn.tsx`) is the form-width column with the `text` sign-out at its foot; a route wraps its state in it, so `TownReadFailed` never draws sign-out itself, since `/report` already holds one around it.
