# apps/android

The native Android client (ADR 034): Kotlin and Jetpack Compose, a renderer of what the api returns. A Gradle project of its own, outside the pnpm workspace. The rules: `.claude/rules/android-architecture.md`, `kotlin-style.md`, `android-testing.md`, `ui-components.md`.

## Commands

Run from `apps/android`.

- `./gradlew detekt checkModuleBoundaries checkComposeFreeViewModels testDebugUnitTest assembleDebug` — the Android leg of the gate, exactly what CI's `android` job runs. Green before every commit that touches `apps/android`, on top of `pnpm gate`.
- `./gradlew detekt` — detekt with the formatting (ktlint) and Compose rule sets, over every module and over `build-logic/convention/src/main/kotlin` (the root project's detekt source), never over `build/`, where the generated client lives. Thresholds live only in `config/detekt/detekt.yml`.
- `./gradlew checkModuleBoundaries` — fails on any project edge the Modules table of `android-architecture.md` does not allow, on `:core:testing` reached through a configuration whose name does not start with `test` or `androidTest`, on a module missing from the table, and on `:core:projection` applying an Android plugin. The table is `allowedCoreEdges` and `allowedFeatureEdges` in `build-logic/convention/.../ModuleChecksConventionPlugin.kt`; a new module is a new entry there and in the rule.
- `./gradlew checkComposeFreeViewModels` — fails on any line of a `*ViewModel.kt` or `*UiState.kt` under any module's `src/` that names `androidx.compose`.
- `./gradlew testDebugUnitTest` — the unit tests of every module. `:core:projection` is a JVM module, so its `testDebugUnitTest` is an alias of `test` that the `mygame.jvm.library` convention registers.
- `./gradlew assembleDebug`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk` and `adb shell am start -n com.emm.mygame/.MainActivity` — the app on a running emulator.

## Layout

- `app` — `MainActivity`, `AppNavigation` and `MyGameApplication` as the composition root (base URL, Keystore cipher, token file, `Dispatchers.IO`). Navigation is Navigation 3: `Destination` holds the `@Serializable` keys (`SignIn`, `SignUp`, `Fief`, `Chronicle`), `rememberNavBackStack` keeps the back stack across recreation and process death, and `Navigator` is the only code that edits it (`NavigatorTest` pins every move): sign-up opens above sign-in, so system back and its *Entra* link both pop to sign-in; signing in or out leaves `Fief` or `SignIn` alone on the stack; *Crónica* opens above *Feudo*, and *Feudo* pops back to it. `NavDisplay` decorates each entry with `rememberSaveableStateHolderNavEntryDecorator` and `rememberViewModelStoreNavEntryDecorator`, so every route's ViewModel is scoped to its entry and cleared when the entry leaves the stack; a new session's view models start fresh with no store to clear. `SignedInFrame` draws `Fief` and `Chronicle` above the `MyGameNavigationBar`. Namespace and `applicationId` `com.emm.mygame`. `BuildConfig.API_BASE_URL`: debug `http://10.0.2.2:3141/` (the host's api from the emulator; cleartext allowed for that host only, by `src/debug`'s network security config), or the `-Pmygame.apiBaseUrl=http://10.0.2.2:<port>/` Gradle property for an api on another port, release `https://mygame.emm3000.com/api/` (the web's `/api` rewrite, ADR 031).
- `feature:signin` — sign-in and sign-up (MVI). A session the api accepts is `SignInEffect.SignedIn` or `SignUpEffect.SignedIn`, sent through each ViewModel's buffered `Channel`; the state stays `Submitting` (or `CheckingSession`), and `SignInRoute` and `SignUpRoute` call `onSignedIn` when they collect it. Each screen links to the other (`onSignUpOpen`, `onSignInOpen`), and `Navigator` moves between them. `SignUpViewModel` sends the email, password and fief name once (a second tap while one waits is dropped), draws the api's `SignUpRefusal` beside the form and offers a retry when the api cannot be reached; it never checks a field itself. While a sign-in or a sign-up is in flight the link to the other screen does nothing (`canSwitchToSignUp`, `canSwitchToSignIn`), so a late answer cannot overwrite the token of a session the player opened on the other screen.
- `feature:fief` — the fief overview: the five resources projected between reads, and the build slot with its countdown (MVI). `FiefViewModel` reads `FiefRepository`, then loops: draws `core:projection`'s amounts at `clock.now()`, waits `repaintDelay` (a minute, a second in the slot's last minute) and re-reads the api when the countdown reaches zero. The *Edificios* section draws one card per building with the next level's cost, duration and peasants, and the reason a card is blocked, checked in the web's order: the queue full, the peasants, the resources at the drawn amounts. A blocked button stays enabled and sends the request anyway (the client never withholds one, `android-architecture.md`); the api's answer is the verdict. `UpgradeTapped` posts once (a second tap while one waits is dropped) and restarts the projection from the overview the api answers, with no second read; a refusal or an outage stays in `UiState.upgrade` beside the card that asked. The queue section, *Obras en espera*, lists every waiting upgrade in order with its countdown and, past an hour, the device-clock time of its finish (`finishLabelOf`), and the busy slot reads the strip's line *Obras en espera: 2 · …* to the last finish. The slot and every waiting entry carry *Cancelar la obra* and the refund line; `CancelTapped` sends one DELETE at a time and restarts from the overview the api answers; a 409 `UpgradeNotFound` re-reads the fief, and an outage stays in `UiState.cancel` beside the entry that asked. It projects at `clock.now()` plus the gap `readAt - clock.now()` stored when the last answer arrived, so a skewed device clock neither overdraws nor re-reads in a loop; a failed re-read keeps the last content and asks again a minute later. The header carries *Salir* in every state: `SignOutTapped` cancels every read and mutation the screen started, so a late answer neither redraws the fief nor sends another request, draws `SigningOut`, awaits `SessionRepository.signOut` and sends `FiefEffect.SignedOut`; `Navigator` then leaves sign-in alone on the back stack, which clears the fief entry's view model. A new `feature:<name>` needs only `settings.gradle.kts`: `checkModuleBoundaries` admits every `:feature:` module with the feature edges.
- `feature:chronicle` — the chronicle (MVI): `ChronicleViewModel` reads `ChronicleRepository` once and draws `Loading`, `Failed` (with *Volver a intentarlo*; a retry reads again only from `Failed`), `Empty` or `Content` with the events in the order the api answers and the `clock.now()` of the read. `ChronicleLine` draws each event as the web's chronicle line: the instant (`Hoy, 14:56`, `30 oct, 15:16`, `28 sept 2025, 15:16` in the device's zone, `chronicleInstantOf`), the bold heading and subject, and the amounts sentence when an amount is above zero; `ChronicleCopy.kt` resolves every phrase from `strings.xml` and joins lists with ICU's Spanish `ListFormatter`.
- `core:network`, `core:testing` — Android libraries; `core:designsystem`, `core:ui` — Android libraries with Compose; `core:projection` — Kotlin JVM. Library namespaces are `com.emm.mygame` plus the module path (`com.emm.mygame.core.designsystem`).
- `build-logic/convention` — the convention plugins every module applies: `mygame.android.application`, `mygame.android.library`, `mygame.android.compose`, `mygame.jvm.library`, and `mygame.module.checks` on the root project. SDK levels (compile and target 37, min 26) and the JVM target (17) live in `ProjectDefaults.kt`.
- `gradle/libs.versions.toml` — every version, exact. `build-logic` reads the same catalog.
- `core:network` — `openApiGenerate` (openapi-generator Gradle plugin, `kotlin` generator, `jvm-retrofit2` with `kotlinx_serialization` and coroutines) generates `../api/openapi.json` as committed, with no rewrite, into `build/generate-resources/main`, wired into compilation by `addGeneratedSourceDirectory`; `openapi-generator-ignore` drops the generated `ApiClient`, auth and Gradle files, since `SessionRepository(...)` builds Retrofit itself. `number` maps to `kotlin.Double` and `integer` to `kotlin.Int`; the mapper turns an amount and a capacity into `Long` and keeps the rate as the `Double` the projection needs, so no `Double` reaches a `UiState`. Every union of the overview (`slot`, `study`, `march`, `goal`) is a named component with a `discriminator` (#590), and `generateOneOfAnyOfWrappers` turns each into a sealed interface (`BuildSlot.IdleWrapper`, `BuildSlot.BusyWrapper`) whose serializer picks the member by the discriminator's value; a value the spec does not list fails the decode. `enumUnknownDefaultCase` is on: an enum value the spec does not list decodes as `unknown_default_open_api`, so a server deploy that adds a terrain or a building leaves every field the screen does not draw harmless; the mapper answers `null` for that case in a field the screen draws (the busy slot's building), and `ApiFiefRepository` answers `Unreachable`. The chronicle's `FiefEvent` union is a named component with a `discriminator` on `kind` too, so it generates `FiefEvent` with one wrapper per member (`UpgradefinishedWrapper`, …). A `kind` the spec does not list would fail the whole decode, so `KnownFiefEventsConverterFactory`, registered before the kotlinx converter, drops from a `FiefChronicle` body every event whose `kind` is not one of the generated `*Event.Kind` values; `toChronicleEvent` then answers `null` for an event naming a building, art, unit or tier the client does not know, and `ApiChronicleRepository` skips it. An unknown event is skipped, never `Unreachable`; a malformed event of a known kind is `Unreachable`. No generated type crosses the module's public API (the repositories over them are `internal`); callers see `SessionRepository`, `SignInResult`, `SignUpResult`, `SignUpRefusal`, `RestoreResult`, `RefusalKind`, `SignedInPlayer`, `FiefRepository`, `FiefReadResult`, `FiefSnapshot`, `FiefId`, `StoredResource`, `ResourceKind`, `BuildSlot`, `BuildingKind`, `BuildingState`, `NextLevel`, `ResourceCost`, `Peasants`, `BuildQueue`, `UpgradeResult`, `UpgradeRefusal`, `WaitingUpgrade`, `CancelResult`, `CancelRefusal`, `ChronicleRepository`, `ChronicleReadResult`, `ChronicleEvent`, `ArtKind`, `UnitKind`, `UnitCount`, `PlotAddress`, `ResourceQuantity`. `ChronicleRepository.read` lists the fiefs, then reads `GET /fiefs/{id}/events` of the first. `FiefSnapshot.buildings` holds the five buildings of the fief screen in their order (sawmill, quarry, iron mine, farm, warehouse); `peasants` reads the overview's `projectedFree` and `projectedSupplied`. `FiefRepository.upgrade` posts `POST /fiefs/{id}/upgrades` and answers the overview the api returns, a 4xx `ApiError` as its `UpgradeRefusal` (`Unrecognized` for a kind the screen does not draw), or `Unreachable`; `FiefRepository.cancel` sends `DELETE /fiefs/{id}/upgrades/{building}/{targetLevel}` and answers the overview, `UpgradeNotFound` or `Unrecognized` as its `CancelRefusal`, or `Unreachable`; `BuildQueue.entries` holds the waiting upgrades in order, and one naming a building the client does not know answers `Unreachable`. `apiError()` (`ApiErrorOf.kt`) decodes a refusal body for every repository. `SessionRepository.signUp` posts `/auth/sign-up/native` and stores the token as sign-in does; a 4xx answers its `SignUpRefusal` (`WeakPassword`, `BlankFiefName`, `EmailTaken`, `MalformedEmail`, or `Unrecognized` for another kind or an empty body (a malformed request, a founding race)), anything else `Unreachable`. `SessionRepository.signOut` posts `/auth/sign-out` with the stored bearer, on its own client whose call timeout is 5 s (sign-in and restore keep no call timeout, since a cold api can take longer), and deletes the token file in a `finally`, whatever the api answers, when it cannot be reached or when the call times out. A Keystore failure never reaches the call: `TokenStore.read` forgets the token, and the request goes without a bearer. `BearerInterceptor` is the one place the bearer is added. `TokenStore` keeps the token as AES/GCM ciphertext under the Keystore key of `KeystoreTokenCipher` in a file in `noBackupFilesDir`; its read and write are `internal`, and its `TokenCipher` is the seam a JVM test fakes.
- Tests: JUnit 4, Turbine, `kotlinx-coroutines-test` on every module's `testImplementation` (`UnitTests.kt` in the conventions); `core:network` tests the repository against OkHttp's `mockwebserver3`. `core:testing` holds `FakeSessionRepository`, `FakeFiefRepository` and `FakeChronicleRepository` (answers queued per call), `FakeTokenCipher`, `MainDispatcherRule` and `TestClock`, which reads the `runTest` scheduler's virtual time so a `delay` advances it. A ViewModel that loops on the clock needs its scope cancelled before `runTest` ends (`backgroundScope.launch(start = CoroutineStart.UNDISPATCHED)` cancelling `viewModelScope`), or the test never finishes. `core:projection` reads `packages/domain/src/resources/projection-cases.json` through the `projection.cases` system property its build sets; a JVM module cannot consume `core:testing`, so its reader lives in its own test sources.
- `core:designsystem` — the tokens, from the web's `apps/web/src/design/tokens.ts` until #572's token source replaces them, except the colors sign-in draws (`surface`, `surfaceRaised`, `surfaceSunken`, `line`, `lineStrong`, `ink`, `inkMuted`, `umber`, `onUmber`, `rust`, `rustSoft`), which carry #572's v29 values: `MyGameColors` (one field per `palette` token, kebab-case to camelCase, `lightColors` and `darkColors` with the same hex), `MyGameTypeFamilies`, `MyGameSpacing` (`step<n>` for `spacing[n]`), `MyGameRadii`, `MyGameTransitions`, `MyGameTypography`, `MyGameSizes`, `MyGameStrokeWidths`, `MyGameIcons`. Components: `MyGameText` (a `String` or an `AnnotatedString`), `MyGameNavigationBar` with `MyGameNavigationItem` (a `Role.Tab`, 48 dp, the current one in bold river with the `currentMark` underline), `MyGameButton` (busy state, a blocked state that keeps it clickable and announces its reason, and an optional `accessibleName` that replaces the label for a screen reader), `MyGameTextField`, `MyGameTextLink`, `MyGameInlineAlert`, `MyGameErrorBanner`, and the `dashedFrame` modifier and `formatQuantity` that more than one feature uses, built on foundation, never Material3. `MyGameTheme { }` provides the colors for the system theme; `MyGameTheme.colors` reads them.

## Gotchas

- Never add a `package.json` here: pnpm takes every directory with one under `apps/*` as a workspace package.
- `local.properties` (`sdk.dir=...`) is gitignored and per machine; CI reads `ANDROID_HOME` from the runner instead.
- AGP 9 compiles Kotlin itself: no `org.jetbrains.kotlin.android` plugin. The Kotlin version comes from `kotlin-gradle-plugin` on `build-logic`'s classpath.
- detekt is 1.23.8 (stable, built against Kotlin 2.0) and runs beside Kotlin 2.4.21 because the `detekt` task parses sources without type resolution. Rules that need type resolution (`UnsafeCallOnNullableType`, for one) report nothing under `detekt`; review still catches `!!`.
- The Compose rules are `io.nlopez.compose.rules:detekt` 0.4.28, the last line built for detekt 1.23. From 0.5 on they target detekt 2.0 and load under 1.23 without error and without running a single rule; probe a new version with a public `@Composable` that emits a `Box` and has no `modifier` before trusting it.
- detekt 1.23.8 uses Gradle APIs deprecated for Gradle 10 (`ReportingExtension.file`, `Configuration.setVisible`); the build warns, nothing fails.
- The configuration cache is on (`gradle.properties`). A custom task reads only its declared inputs; both check tasks live in `build-logic/convention` (where detekt lints them; it never reads `.kts`), registered on the root project by `mygame.module.checks`, and gather their inputs in `gradle.projectsEvaluated`.
- `core:network`'s tests depend on `core:testing`, which depends on `core:network`; Gradle resolves it because only the test configuration closes the loop.
