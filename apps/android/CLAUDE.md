# apps/android

The native Android client (ADR 034): Kotlin and Jetpack Compose, a renderer of what the api returns. A Gradle project of its own, outside the pnpm workspace. The rules: `.claude/rules/android-architecture.md`, `kotlin-style.md`, `android-testing.md`, `ui-components.md`. This file holds only the commands and the traps nothing else catches.

## Commands

Run from `apps/android`. Every Gradle command runs as `taskpolicy -c utility ./gradlew …`: a Gradle daemon keeps the priority it started with, so one run without the prefix leaves a full-priority daemon behind. CI's `ci.yml` runs plain `./gradlew`, since Linux has no `taskpolicy`.

- `taskpolicy -c utility ./gradlew detekt checkModuleBoundaries checkComposeFreeViewModels checkStructure testDebugUnitTest assembleDebug` — the Android leg of the gate, exactly what CI's `android` job runs. Green before every push that touches `apps/android`, on top of `pnpm gate`.
- `taskpolicy -c utility ./gradlew detekt` — ktlint formatting and the Compose rules over every module and `build-logic/convention/src/main/kotlin`. Thresholds live only in `config/detekt/detekt.yml`.
- `taskpolicy -c utility ./gradlew checkModuleBoundaries` — the Modules table of `android-architecture.md`, held as `allowedCoreEdges` and `allowedFeatureEdges` in `build-logic/convention/.../ModuleChecksConventionPlugin.kt`. A new `core:` module is a new entry there and in the rule; a new `feature:` module needs only `settings.gradle.kts`.
- `taskpolicy -c utility ./gradlew checkComposeFreeViewModels` — fails on any `*ViewModel.kt` or `*UiState.kt` line that names `androidx.compose`.
- `taskpolicy -c utility ./gradlew checkStructure` — the limits and checks of ADR 056, sections 6 and 7, their numbers held only in `build-logic/convention/.../StructureLimits.kt`, after `build-logic`'s own tests. Fails on a violation `config/structure/baseline.txt` does not hold and on a baseline line that no longer violates: the step that fixes a file deletes its line.
- `taskpolicy -c utility ./gradlew testDebugUnitTest` — every module's unit tests; on the JVM modules `:core:model`, `:core:projection` and `:core:testing` it is an alias of `test`.
- `taskpolicy -c utility ./gradlew :core:designsystem:recordRoborazziDebug` — rewrites the Roborazzi goldens in `core/designsystem/src/test/screenshots/` after an intended visual change. `roborazzi.test.verify=true` in `gradle.properties` makes `testDebugUnitTest` verify every `captureRoboImage` against its golden, so a drawn change committed without a re-record fails the gate.
- The peer's own emulator, the AVD `mygame-<name>` (`docs/agents/peer.md`, Isolation):
  - create: `$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager create avd -n mygame-<name> -k "system-images;android-36;google_apis_playstore;arm64-v8a" -d medium_phone`;
  - set `hw.gpu.enabled=yes`, `hw.gpu.mode=host` and `hw.ramSize=4G` in `${ANDROID_AVD_HOME:-$HOME/.android/avd}/mygame-<name>.avd/config.ini`, since `avdmanager` leaves the GPU off and software rendering takes about 5 cores;
  - start, detached, from a foreground Bash call: `nohup $ANDROID_HOME/emulator/emulator -avd mygame-<name> -port <port> -no-window -no-audio -gpu host >"<log>" 2>&1 </dev/null &` as the last command of its call, `<log>` being `<scratchpad>/emulator.log` in a Claude session and `${TMPDIR:-/tmp}/mygame-<name>-emulator.log` outside one, on an even port in 5560–5588 that `adb devices` does not list, and pass `-s emulator-<port>` to every `adb` command below. Ports 5590 and up belong to pichanga. The detached start keeps `netsimd` out of your session's process group, which the session's end kills (`docs/agents/multi-session.md`, Isolation: emulators);
  - `scripts/mygame-wave-close` stops it and deletes the AVD at close-out.
- `taskpolicy -c utility ./gradlew assembleDebug`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk` and `adb shell am start -n com.emm.mygame/.MainActivity` — the app on a running emulator, against the host's api at `http://10.0.2.2:3141/`; `-Pmygame.apiBaseUrl=http://10.0.2.2:<port>/` points it at another port.
- Once per machine, the release key, outside the repo and backed up: `mkdir -p ~/keys`, then `keytool -genkeypair -v -keystore ~/keys/mygame-release.jks -alias mygame -keyalg RSA -keysize 4096 -validity 10000`. The keystore is PKCS12, so `keyPassword` takes the same value as `storePassword`.
  - Four lines in `~/.gradle/gradle.properties`: `mygame.release.storeFile=/absolute/path/to/mygame-release.jks`, `mygame.release.storePassword=…`, `mygame.release.keyAlias=mygame`, `mygame.release.keyPassword=…`.
  - Or the variables `MYGAME_RELEASE_STORE_FILE`, `MYGAME_RELEASE_STORE_PASSWORD`, `MYGAME_RELEASE_KEY_ALIAS`, `MYGAME_RELEASE_KEY_PASSWORD`. A Gradle property wins over its variable.
  - The key is the app's identity: losing it means uninstalling the app on the phone, and its stored session, before a build under a new key installs.
- `taskpolicy -c utility ./gradlew assembleRelease`, then `adb install -r app/build/outputs/apk/release/app-release.apk` — the signed APK for a phone; `apksigner verify --print-certs` prints its certificate. With none of the four set it writes `app-release-unsigned.apk` and exits 0; with only some set it fails, naming all four.
  - `versionCode` reads `mygame.versionCode`, then `MYGAME_VERSION_CODE`, then 1. `app-distribution.yml` sets the variable to the run number and sends the signed build to Firebase App Distribution (`.claude/rules/github-workflows.md`).
- `taskpolicy -c utility ./gradlew assembleLocalRelease` — the release build against a local api (`-Pmygame.apiBaseUrl`, default `http://10.0.2.2:3141/`), installed beside the others as `com.emm.mygame.local`: `adb install -r app/build/outputs/apk/localRelease/app-localRelease.apk` and `adb shell am start -n com.emm.mygame.local/com.emm.mygame.MainActivity`.

## Gotchas

- Every `strings.xml` is generated by `pnpm --filter @mygame/catalog generate` from `en.json` and `es.json` (`android.<module>.<name>`); a hand edit fails the drift test in `pnpm gate`.
- A string is ICU MessageFormat with named arguments: a plural is one string, so there is no `R.plurals` or `pluralStringResource`; a number argument passes its `toString()` and a plural count is `{count, number,0}`, so locale grouping never reaches it.
- `app`'s and each feature's `robolectric.properties` set `qualifiers=es`, so a screen test that names no language reads the Spanish; every one pins `sdk=34`, since Robolectric needs Java 21 above that and CI runs Java 17, and `graphicsMode=NATIVE`, since the default LEGACY mode measures text falsely: a new module's file carries both.
- Resource names are one namespace: with `nonTransitiveRClass` a clash compiles, and the merged APK silently keeps the first dependency's value. Prefix each module's names (`report_`, `designsystem_`). `feature:account`'s screen prefixes are `sign_`, `forgot_`, `reset_`, `verify_`, `verification_`, `settings_` and `scaffold_`: they are that module's own, and no other module uses them.
- Clash guards, each printing nothing: `rg -No --no-filename 'name="[^"]+"' apps/android -g '**/src/main/res/values/*.xml' | sort | uniq -d` and `fd -p -g '**/src/main/res/drawable*/*.xml' apps/android -E build -x basename {} | sort | uniq -d`.
- Never add a `package.json` here: pnpm takes every directory with one under `apps/*` as a workspace package.
- AGP 9 compiles Kotlin itself: no `org.jetbrains.kotlin.android` plugin; the Kotlin version comes from `kotlin-gradle-plugin` on `build-logic`'s classpath.
- detekt 1.23.8 runs without type resolution, so rules that need it (`UnsafeCallOnNullableType`) report nothing and review catches `!!`. It is the build's one source of a Gradle 10 deprecation, `ReportingExtension.file(String)` (detekt/detekt#8452), and with `org.openapi.generator` 7.26.0 the source of `Configuration.setVisible(boolean)`, removed in Gradle 11 (detekt/detekt#9558, OpenAPITools/openapi-generator#25025). detekt fixes both only on its 2.0 line, and neither warning fails the build. `--warning-mode all` names them, and `build/reports/problems/problems-report.html` names each one's plugin.
- The Compose rules stay on `io.nlopez.compose.rules:detekt` 0.4.28: from 0.5 they target detekt 2.0 and load under 1.23 without running a rule. Probe a new version with a public `@Composable` that has no `modifier`.
- The configuration cache is on: a custom task reads only declared inputs, gathered in `gradle.projectsEvaluated` by `mygame.module.checks`, which lives in `build-logic/convention` because detekt never reads `.kts`.
- The study reminder's tap is a `PendingIntent.getActivity` straight to `MainActivity` (`StudyReminderAlarm.tapping`): Android 12 forbids a receiver trampoline, and no test pins the target, since `MainActivityReminderTapTest` starts `MainActivity` itself.
- A route collects its effects inside `withContext(Dispatchers.Main.immediate)`: on the composition's dispatcher an effect taken just before a recreation is lost.
- Debug and release share `com.emm.mygame` but not a signature: `adb install -r` of one over the other fails `INSTALL_FAILED_UPDATE_INCOMPATIBLE`; `adb uninstall com.emm.mygame` first, which signs the player out.
- R8 is off for `release`: the APK goes only to the owner's phone, and a missed keep rule (kotlinx.serialization wrappers, Navigation 3 keys) crashes only on a minified build. Turning it on means walking the whole flow on a minified `localRelease`.

A PR adds a gotcha here only when it is a trap no code, rule or test catches, in one line, and never narrates its module.
