# apps/android

The native Android client (ADR 034): Kotlin and Jetpack Compose, a renderer of what the api returns. A Gradle project of its own, outside the pnpm workspace. The rules: `.claude/rules/android-architecture.md`, `kotlin-style.md`, `android-testing.md`, `ui-components.md`.

## Commands

Run from `apps/android`.

- `./gradlew detekt checkModuleBoundaries checkComposeFreeViewModels testDebugUnitTest assembleDebug` — the Android leg of the gate, exactly what CI's `android` job runs. Green before every commit that touches `apps/android`, on top of `pnpm gate`.
- `./gradlew detekt` — detekt with the formatting (ktlint) and Compose rule sets, over every module and over `build-logic/convention/src/main/kotlin` (the root project's detekt source), never over `build/`, where the generated client lives. Thresholds live only in `config/detekt/detekt.yml`.
- `./gradlew checkModuleBoundaries` — fails on any project edge the Modules table of `android-architecture.md` does not allow, on `:core:testing` reached through a configuration whose name does not start with `test` or `androidTest`, on a module missing from the table, and on `:core:projection` applying an Android plugin. The table is `allowedCoreEdges` and `allowedFeatureEdges` in `build-logic/convention/.../ModuleChecksConventionPlugin.kt`; a new module is a new entry there and in the rule.
- `./gradlew checkComposeFreeViewModels` — fails on any line of a `*ViewModel.kt` or `*UiState.kt` under any module's `src/` that names `androidx.compose`.
- `./gradlew testDebugUnitTest` — the unit tests of every module. `:core:projection` is a JVM module, so its `testDebugUnitTest` is an alias of `test` that the `mygame.jvm.library` convention registers.
- `./gradlew assembleDebug`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk` and `adb shell am start -n com.emm.mygame/.MainActivity` — the app on a running emulator.
- Once per machine, the release key: `mkdir -p ~/keys`, then `keytool -genkeypair -v -keystore ~/keys/mygame-release.jks -alias mygame -keyalg RSA -keysize 4096 -validity 10000`, with the keystore outside the repo and backed up. `keytool` writes a PKCS12 keystore, which keeps one password for the store and the key, so `keyPassword` takes the same value as `storePassword`. Then four lines in `~/.gradle/gradle.properties`: `mygame.release.storeFile=/absolute/path/to/mygame-release.jks`, `mygame.release.storePassword=…`, `mygame.release.keyAlias=mygame`, `mygame.release.keyPassword=…`; or the environment variables `MYGAME_RELEASE_STORE_FILE`, `MYGAME_RELEASE_STORE_PASSWORD`, `MYGAME_RELEASE_KEY_ALIAS`, `MYGAME_RELEASE_KEY_PASSWORD`. A Gradle property wins over its variable.
- `./gradlew assembleRelease`, then `adb install -r app/build/outputs/apk/release/app-release.apk` — the signed APK for a phone; `apksigner verify --print-certs` on it prints the key's certificate. With none of the four set it writes `app-release-unsigned.apk` and exits 0, so CI needs no secret; with only some set the configuration fails, naming all four.
- `./gradlew assembleLocalRelease` — the release build type, signed the same way, pointed at `-Pmygame.apiBaseUrl` (default `http://10.0.2.2:3141/`) with `src/debug`'s network security config: the release build against a local api on the emulator. Its `applicationIdSuffix` makes it `com.emm.mygame.local`, so it installs beside the debug or release app: `adb install -r app/build/outputs/apk/localRelease/app-localRelease.apk` and `adb shell am start -n com.emm.mygame.local/com.emm.mygame.MainActivity`.

## Layout

- `app` — `MainActivity`, `AppNavigation` and `MyGameApplication` as the composition root (base URL, Keystore cipher, token file, `Dispatchers.IO`). Navigation is Navigation 3: `Destination` holds the `@Serializable` keys (`SignIn`, `SignUp`, `ForgotPassword`, `FirstFief`, `Fief`, `Map`, `Chronicle`; `Fief`, `Map` and `Chronicle` each carry the `FiefId` they read, itself `@Serializable`, and `DestinationTest` round-trips them through the serializer), `rememberNavBackStack` keeps the back stack across recreation and process death, and `Navigator` is the only code that edits it (`NavigatorTest` pins every move): sign-up and the reset request (`ForgotPassword`) each open above sign-in only, so system back, sign-up's *Entra* link and the reset request's *Entra en tu feudo* link all pop to sign-in; signing in, signing up or a restored session leaves `FirstFief` alone on the stack, and signing out leaves `SignIn`; `FirstFiefRoute` (`feature:fief`, the web's `_signedIn/index`) lists the fiefs once through `FiefListRepository.firstListed` and calls `Navigator.firstFiefOpened` with the first one, which leaves `Fief` of that id alone on the stack only while `FirstFief` is on top; an empty list (*No encontramos tus tierras.*) or an outage draws its line in a `MyGameErrorBanner` with *Volver a intentarlo*, which lists again; the header row carries *Salir* beside the brand in every state, as on *Feudo*, so an outage never traps the lord: `FirstFiefIntent.SignOutTapped` cancels the listing in flight, so a late answer opens no fief, draws `SigningOut` with the button busy, awaits `SessionRepository.signOut` once (a second tap is dropped) and sends `FirstFiefEffect.SignedOut`, which `AppNavigation` hands to `signedOut(isSessionEnded = false)`; `SignIn` carries `isSessionEnded`, `false` at a cold start and after *Salir*, `true` when the session ended under the player: `AppNavigation` runs `Navigator.followSessionEnds` over `MyGameApplication.sessionEnds.ended`, which calls `signedOut(isSessionEnded = true)` on each report, and a report while that sign-in is already alone on the stack changes nothing; *Mapa* and *Crónica* each open above *Feudo* with the id of the fief on top, either one opened from the other takes its place with the same id, so the stack never holds both, and *Feudo* or system back pops back to *Feudo*; no tab opens above `FirstFief`, which draws no tabs. `NavDisplay` decorates each entry with `rememberSaveableStateHolderNavEntryDecorator` and `rememberViewModelStoreNavEntryDecorator`, so every route's ViewModel is scoped to its entry and cleared when the entry leaves the stack; a new session's view models start fresh with no store to clear. `SignedInFrame` draws `Fief`, `Map` and `Chronicle` above the `MyGameNavigationBar`, whose tabs read *Feudo*, *Mapa*, *Crónica*. The box that holds the screen fits inside the keyboard (`fitInside(WindowInsetsRulers.Ime.current)`) and consumes the navigation bars and the IME, so the IME inset is applied once, there, and a screen's `safeDrawingPadding` adds none: with the keyboard open the screen ends at the keyboard's top and the tabs stay under it. Above each of the three it draws the fief switcher, *Tus feudos* (`FiefSwitcher`, the web's `FiefSwitcher`), from a `FiefSwitcherViewModel` scoped to the entry: each composition of the frame sends `ScreenShown`, which reads `FiefListRepository.listed` again (a newer read cancels an older one); a failed read keeps the last entries, and while none was read the frame draws no switcher and leaves the status bar to the screen. One entry per listed fief in the api's order, two to a row, each at least 48 dp: the name as the lord gave it and the address *Vadoalto 3:12*; the fief on screen is drawn with a river frame and bar and its name in bold, announced as *Feudo actual*, and carries no badge; every other fief is a button with its badges, one per `freeSlots` (*Sin obra*, *Sin estudio*, *Sin leva*, *Sin marcha*) and then one per `fullStores` (*Almacén lleno: piedra*, with the resource's icon), the web's order. Choosing one calls `Navigator.switchFief`, which keeps the screen: `[Fief(a)]` becomes `[Fief(b)]`, `[Fief(a), Map(a)]` becomes `[Fief(b), Map(b)]` and the chronicle likewise, so *Mapa* and *Crónica* are never both on the stack and *Feudo* stays below them; the fief on screen changes nothing, and nothing moves while *Salir* waits. `FiefRoute`'s `onNewFief` sends the switcher `FoundingApplied`, which reads the list again without leaving *Feudo*. While *Salir* waits, `FiefRoute` calls `Navigator.signingOut`: `openMap` and `openChronicle` leave the back stack unchanged, and `areTabsEnabled` draws the three tabs in place but disabled (`MyGameNavigationItem`'s `isEnabled`), announced as disabled tabs; `signedOut` enables them again for the next session. Namespace and `applicationId` `com.emm.mygame` (`com.emm.mygame.local` for `localRelease`). `BuildConfig.API_BASE_URL`: debug `http://10.0.2.2:3141/` (the host's api from the emulator; cleartext allowed for that host only, by `src/debug`'s network security config), or the `-Pmygame.apiBaseUrl=http://10.0.2.2:<port>/` Gradle property for an api on another port, release `https://mygame.emm3000.com/api/` (the web's `/api` rewrite, ADR 031), `localRelease` the debug value with the debug network security config. `release` is signed only when the four `mygame.release.*` settings are present (`signingConfigs.findByName("release")`), and runs without R8: `isMinifyEnabled` and `isShrinkResources` are `false` (Gotchas).
- `feature:signin` — sign-in, sign-up and the reset request (MVI). A session the api accepts is `SignInEffect.SignedIn` or `SignUpEffect.SignedIn`, sent through each ViewModel's buffered `Channel`; the state stays `Submitting` (or `CheckingSession`), and `SignInRoute` and `SignUpRoute` call `onSignedIn` when they collect it. Every route collects its effects inside `withContext(Dispatchers.Main.immediate)`: on the composition's own dispatcher an effect taken from the channel just before the activity is recreated would be lost, and the form would stay `Submitting`. Each screen links to the other (`onSignUpOpen`, `onSignInOpen`), and `Navigator` moves between them. `SignInViewModel` takes `isSessionEnded` from the route's key and draws *Tu sesión ha terminado. Entra de nuevo en tu feudo.* in a `MyGameInlineAlert` above the fields until the player submits. The fields carry the web's autofill types: sign-in's email `EmailAddress` and password `Password`, sign-up's email `EmailAddress`, password `NewPassword` (with *Al menos 8 caracteres.* as its `supportingText`) and fief name none. `SignUpViewModel` sends the email, password and fief name once (a second tap while one waits is dropped), draws the api's `SignUpRefusal` beside the form and offers a retry when the api cannot be reached; it never checks a field itself. While a sign-in or a sign-up is in flight the link to the other screen does nothing (`canSwitchToSignUp`, `canSwitchToSignIn`), so a late answer cannot overwrite the token of a session the player opened on the other screen; the same guard holds sign-in's *¿Has olvidado tu contraseña?* link, drawn under the submit, which opens `ForgotPasswordRoute`. `ForgotPasswordScreen` (the web's `ForgotPasswordScreen`) reads *Recupera tu contraseña*, the field *Correo* (autofill `EmailAddress`) and *Enviar enlace*; `ForgotPasswordViewModel` sends the email as typed once (a second tap while one waits is dropped) and checks no field, leaving the shape to the api's 400. `Requested` replaces the form with *Si ese correo tiene un feudo y está confirmado, te llegará un enlace que vale una hora.* (a polite live region); `MalformedEmail` draws *Escribe un correo válido, como nombre@ejemplo.com.* and `Unreachable` the *Unexpected* line, each in a `MyGameInlineAlert` beside the kept form, where *Enviar enlace* asks again. It has no effect channel: the only way out is the *Entra en tu feudo* link, under the form and under the confirmation. The mail's link opens the web's new password screen; no deep link reaches the app.
- `feature:fief` — the fief overview: the five resources projected between reads, and the build slot with its countdown (MVI). `FiefViewModel` reads `FiefRepository` for the route's `FiefId`, then loops: draws `core:projection`'s amounts at `clock.now()`, waits `repaintDelay` (a minute, a second in the last minute of the nearest countdown, the season's included) and re-reads the api when the countdown reaches zero. Under the fief name the header draws the season line (`SeasonLine`, `UiState.season`, the web's `SeasonLineOf`): the season's icon, *Otoño, año 1* and, after a `·` hidden from TalkBack, the countdown *Invierno en 3 días* to the next season (after winter, spring), in whole days while at least one day is left (`SeasonCountdown.InDays`), from a minute in `countdownLabelOf`'s form (`SeasonCountdown.UnderADay`), and under a minute in seconds down to *0 s*, never *Terminada*, while the read at `endsAt` waits or fails (`SeasonCountdown.InSeconds`), repainted on the loop's cadence; with no season in the overview it draws nothing of the season (`SeasonContent.kt`). Each *Recursos* row whose season `multiplierPercent` is not 100 draws, under its rate line and above its bar, the season mark (`ResourceLine.seasonMark`, `seasonMarkOf`, the web's `seasonMarkOf`): `MyGameSeasonMark` with the season's icon and *Otoño: +25 % de oro* or *Invierno: -25 % de comida*, the signed change from 100 with an ASCII sign; a resource at 100, every resource in summer and every resource with no season draw none; the row's one `contentDescription` reads the mark's words after its own (`ResourceRowTest`). The *Edificios* section draws one card per building with the next level's cost, duration and peasants, and the reason a card is blocked, checked in the web's order: the queue full, the peasants, the resources at the drawn amounts. A card blocked by the resources alone, the building, unit and art cards alike, carries the ready hour beside its reason (`ReadyTerms.kt`, the web's `readyLineOf`): per short resource, from the read's stored amount, rate and capacity and `readAt`, the whole minutes to its cost, one more when `ResourceStock.amountAt` at that minute is still below it, the latest across them; none at a rate of 0 or a cost above the capacity. `ReadyHour.InMinutes` reads *lista en 48 min* (at least 1), `ReadyHour.InAnHour` *lista en 1 h*, `ReadyHour.AtClock` *lista 20:00* on the device clock (the server instant minus the gap, rounded up to the minute) through `clockLabelOf`; `BlockedReasonLine` draws it beside the reason and the button's `blockedReason` reads both. A blocked button stays enabled and sends the request anyway (the client never withholds one, `android-architecture.md`); the api's answer is the verdict. `UpgradeTapped` posts once (a second tap while one waits is dropped) and restarts the projection from the overview the api answers, with no second read; a refusal or an outage stays in `UiState.upgrade` beside the card that asked. The queue section, *Obras en espera*, lists every waiting upgrade in order with its countdown and, past an hour, the device-clock time of its finish (`finishLabelOf`), and the busy slot reads the strip's line *Obras en espera: 2 · …* to the last finish. The slot and every waiting entry carry *Cancelar la obra* and the refund line; `CancelTapped` sends one DELETE at a time and restarts from the overview the api answers; a 409 `UpgradeNotFound` re-reads the fief, and an outage stays in `UiState.cancel` beside the entry that asked. It projects at `clock.now()` plus the gap `readAt - clock.now()` measured when the last read arrived, so a skewed device clock neither overdraws nor re-reads in a loop; a mutation's answer keeps that gap, since every mutation now answers `readAt` at the server's mutation instant (#621) and the read stays the single measure of the gap; a failed re-read keeps the last content and asks again a minute later. The header carries *Salir* in every state: `SignOutTapped` cancels every read and mutation the screen started, so a late answer neither redraws the fief nor sends another request, draws `SigningOut`, awaits `SessionRepository.signOut` and sends `FiefEffect.SignedOut`; `Navigator` then leaves sign-in alone on the back stack, which clears the fief entry's view model. From library level 1 the *Biblioteca* section (`LibrarySection`, `UiState.library`, `null` below level 1) draws the study slot (*La biblioteca no tiene estudio en marcha.*, or the art under way with its countdown, *Cancelar el estudio* and *Si lo cancelas, recuperas …* from `StudySlot.Busy.cost`, the cost the study debited, never the art's next-level cost, which may have changed since (N5)) and one card per art with its level (*sin estudiar*), its rate line as the web's `study.effect` with the api's number kept, so a rate of 7.5 reads *+7,5 %* and a whole one *+5 %* (`percentLabelOf`), the next level's cost and duration, *Requiere biblioteca a nivel 2* in rust while the library is below it, and the reason the study is blocked (`NextArtLine.block`, a `StudyBlock`), checked in the web's `artCardOf` order: the study slot busy (*Ya hay un estudio en marcha.*), the library's level (*Necesitas la biblioteca a nivel 2 y está a nivel 1.*), the resources at the drawn amounts (*Te faltan 150 de hierro.*); the button stays enabled and sends anyway. `StudyTapped` and `StudyCancelTapped` share one `UiState.library.study` status: one request at a time (a second tap while one waits is dropped), the answer restarts the projection, a 409 `StudyNotFound` re-reads the fief and keeps its line, and every other `StudyRefusal` or an outage stays beside the section until the next read. From barracks level 1 the *Cuartel* section (`ArmySection`, `UnitItem`, `UiState.army`, `null` below level 1) draws the levy slot (*El cuartel no tiene leva en marcha.*, or *Leva en marcha: 4 de 12 infantes* with *Leva completa en …*, *Cancelar la leva* named *Cancelar la leva: 12 infantes*, and *Si la cancelas, recuperas lo de 8 infantes de vuelta al campo: …* from the undelivered units' cost) and one card per unit kind in the contract's order with *12 infantes en casa* (the units on the march apart, the units delivered since the read added). A kind above the built level is `UnitCard.Locked` (*Requiere cuartel de nivel 3*, *Necesitas un cuartel de nivel 3 y el tuyo es de nivel 1.*); an open one carries the *Infantes a reclutar* entry (`RecruitEntryChanged`, kept in `Mutations.recruitEntries`, `1` by default), the cost, peasants and duration of the count, and the reason it is blocked in the web's order: the levy running, the count, the peasants, the resources. Sending a levy, by the button or the keyboard's *Done*, and *Cancelar la leva* clear the focus before the intent, so no field keeps the keyboard or takes it back when the cancel makes it writable; the focus stays in the composables (`ArmySectionFocusTest`). `recruitCountOf` reads the entry: blank, `0`, a negative or a fraction is `RecruitBlock.InvalidCount` and `RecruitTapped` sends nothing; that is input parsing, not a game rule. `RecruitTapped` and `RecruitCancelTapped` share one `UiState.army.recruit` status, as the library does: one request at a time, the answer restarts the projection, a 409 `RecruitOrderNotFound` re-reads the fief and keeps its line, and every other `RecruitRefusal` (with the unit and the level its kind requires, for `BarracksTooLow`) or an outage stays beside the section until the next read. The delivered count is `core:projection`'s `deliveredUnitsAt` (the web's `recruitOrderAt`). The *Cuartel* section also draws the march slot (`MarchSlot`, `UiState.army.march`): *El cuartel no tiene marcha en curso.*, or `MarchSlotLine.Busy` with its `MarchHeading` over the phase line, its `MarchDetail`, its `MarchCountdown` and the loot, the web's `marchPhaseLineOf`, `marchCountdownOf` and `detailLineOf`: a forage, or any recalled order but a transport, reads *Marcha de ida:*, *Forrajeo:* or *Marcha de vuelta:*; an attack reads *Marcha al ataque:* before its arrival and *Vuelta del ataque:* from it, with *Campamento: nivel 2, fuerza 15* while not recalled; a founding on the way reads *Marcha de fundación:*, *Nuevo feudo: Vega* and *Llegada en* to its arrival; a transport reads *Marcha de transporte:* outbound with *Carga:* and *Llegada en* to its arrival, *Vuelta del transporte:* from it (the *Carga:* line kept only when recalled), and never a loot line. *Batalla:* is the map's attack preview line, never the slot's. While outbound or foraging, *Retirar la marcha* named *Retirar la marcha: 12 infantes*. The phase is `core:projection`'s `marchPhaseAt` (the web's `marchAt`), redrawn at each turn (`nextMarchTurnAt`) without a read. `RecallTapped` posts the recall naming `departedAt`, one at a time, and restarts from the answer; `MarchAlreadyReturning` stays in `UiState.army.recall`, and `MarchNotFound` re-reads the fief. The loop re-reads when the build slot, the study, the levy or the march reaches zero, at the arrival of an attack neither fought nor recalled (`battleRemainingAt`, the web's `battleRemainingSecondsAt`), so the battle's answer draws the survivors, and once at the season's `endsAt` (`seasonRemainingAt`, the web's `seasonRemainingSecondsAt`), so the next season's rates draw the amounts and the ready hour; with no season it reads nothing more (`nextFinishAt`). Unlike the web it never re-reads every 60 s. Every read or mutation answer that drops a founding on the way (a `Found` march, not recalled, whose `departedAt` the new answer no longer holds) sends `FiefEffect.FoundingApplied`, which `FiefRoute` hands to `onNewFief`, so the switcher lists the new fief (`docs/lore/names.md`, The marches, At the arrival); the web reads the list only on navigation. `FiefRoute` sends `ScreenShown` each time the entry is composed and `ScreenHidden` when it leaves composition, as when *Mapa* or *Crónica* opens above it. `ScreenHidden` cancels the loop, so a finish passing while hidden reads nothing, and a mutation answered while hidden is kept without restarting it. `ScreenShown` after a hide re-reads the fief once from `Content`, so a march sent from *Mapa* shows when *Feudo* comes back (an outage restarts the loop from the last read), and reads again from `Loading` when the first read was hidden before its answer; the first composition reads nothing more. A new `feature:<name>` needs only `settings.gradle.kts`: `checkModuleBoundaries` admits every `:feature:` module with the feature edges.
- `feature:chronicle` — the chronicle (MVI): `ChronicleViewModel` reads `ChronicleRepository` once for the route's fief and draws `Loading`, `Failed` (with *Volver a intentarlo*; a retry reads again only from `Failed`), `Empty` or `Content` with the events in the order the api answers and the `clock.now()` of the read. `ChronicleLine` draws each event as the web's chronicle line: the instant (`Hoy, 14:56`, `30 oct, 15:16`, `28 sept 2025, 15:16` in the device's zone, `chronicleInstantOf`), the bold heading and subject, and the amounts sentence when an amount is above zero, each amount led by its resource icon in the resource's accent (`amountMarksOf` gives where each amount's words start), the icons drawn as inline content and the sentence's words alone given to TalkBack (`ChronicleLineTest`); `ChronicleCopy.kt` resolves every phrase and instant from `strings.xml` as `Resources` extensions and joins lists with ICU's Spanish `ListFormatter`; `ChronicleCopyTest` runs it under Robolectric against the real strings.
- `feature:map` — the kingdom map, read-only (MVI): `MapViewModel` reads `MapRepository.readOwn` of the route's fief first and draws `Loading`, `Failed` (with *Volver a intentarlo*, which reads again the province that failed), `ProvinceNotFound` (the not-found line with *Ir a tu provincia*, which reads the own province again) or `Content`: the heading *Vadoalto, provincia 3*, *Terreno: vega* and one line per plot in the api's order. *Provincia anterior* is not offered at province 1 nor *Provincia siguiente* at `lastProvince`; *Ir a la provincia* reads the number typed in its field, past `lastProvince` included, which the api answers with `ProvinceNotFound`, and ignores an entry that names no province. Every browse draws `Loading` until the answer, and no control is drawn while it waits, so one read is in flight at a time. `MapCopy.kt` resolves the heading, the terrain and the plot lines from `strings.xml` as `Resources` extensions, in the register of `docs/lore/names.md` (The map): *Parcela 7: libre*, *Parcela 12: Sotoverde*, *Parcela 12* with *Tu feudo: Sotoverde* under it, *Parcela 7: campamento de bandidos, nivel 2, fuerza 15*, *Parcela 7: reservada* and *Parcela 7: reservada · Tu fundación*; `MapCopyTest` runs it under Robolectric against the real strings. `MapViewModel` also reads `FiefRepository` once for the route's fief (again with the next map read while it failed); once read, `offersOn` (`PlotOffers.kt`, the web's `plotActionsOf`) gives each plot its `PlotOffer`s: a `PlotHolder.Free` plot *Enviar una marcha a parcela 7* and, with a settler at home, *Fundar un feudo en parcela 7*; a `Camp` *Atacar el campamento en parcela 7*; an `Own` plot whose `fief` is the lord's other fief *Enviar un transporte a parcela 7*; a reservation, a held plot and the fief the map is read from none. `ForageToggled`, `AttackToggled`, `FoundingToggled` (with the proposed name the screen resolves, the terrain capitalised, *Vega*) and `TransportToggled` open the form under that plot from one `MarchChoice` (the `ChosenOrder`, the party entries, the hours, the name and the cargo entries); the same plot and order close it, another order on the same plot replaces it. The party fields are *Infantes a enviar*, *Jinetes a enviar*, *Arqueros a enviar* (never a settler; the first kind at home starts at `1`). `ForageForm.kt` holds the web's `marchFormOf`: the units at home (count minus away), the road (`ceil(base * slowest road percent * season road / 10000)`), the return (`2 * road + hours`) and the loot (gold never, each yielded resource capped at the carry share, the season's loot percent applied), and the block in the web's order (a march away, the count, the hours, an empty party, the first kind short). `AttackForm.kt` holds the web's `attackFormOf` and `partyBattleOf` over `combatTerms` and each `UnitState.strength`: no hours, the return twice the road, a win when the party's strength exceeds the camp's, losing `ceil(C² / S)` strength in party-kind order with the last kind reached spared, a loss losing every man and the camp `min(C - 1, ceil(S² / C))`, and the loot `floor(min(lootPerStrength * C, carry of the survivors) / (yielded + 1))` for each yielded resource and gold, with no season. `FoundingForm.kt` sends one settler and the name trimmed; its block reads a march away, a blank name (no preview), no settler at home. `TransportForm.kt` adds *Madera a enviar* and the other four amounts (`0` each), the preview *Carga: 300 de 600* with the road and *Llegada en* once the party is not empty, and the block in the web's order: a march away, a count or amount that is not whole, the party, an empty cargo, the cargo above the carry, the amounts above the stored stocks. A blocked form sends nothing, as the web's `MarchForm` runs `onSend` only for an affordable state: `SendTapped`, from the button or the keyboard's *Done*, posts only while the form's `block` is `null`, so a blocked form draws its reason as its only line; `MyGameButton` stays clickable and the gate is the ViewModel's. `SendTapped` posts once and draws the overview's march under the plot (`SentForage`, `SentAttack`, `SentFounding`, `SentTransport`), then reads the province shown again without drawing `Loading`, keeping the sent line and the jump entry, so a founding's plot reads *Parcela 7: reservada · Tu fundación* (the web's `onSent` → `reread`); a newer re-read or a browse cancels that read, and a re-read that fails keeps the content; a `MarchRefusal` or an outage stays in the form; `NotEnoughUnitsAtHome`, `StayOutOfRange`, `FiefCapReached` and `CargoAboveCarry`, whose line the api builds from the refusal, keep the api's `message` verbatim (`SendStatus.RefusedWithApiLine`, the web's `marchRefusalLineOf`), and every other kind its `strings.xml` line. The api's line covers what the client did not foresee, such as a fief that changed since its read. Any map read drops the form. Sending a march from any form, by the button or the last field's *Done*, and jumping to a province, by the *Ir a la provincia* button or the field's *Go*, clear the focus before the intent, so no field keeps the keyboard, nor takes it back when a refusal makes the form writable again; the focus stays in the composables (`MapFocusTest`). `MarchCopy.kt` resolves the forms, `MarchAnswerCopy.kt` the sent lines and the refusals, `MarchPhraseCopy.kt` the party, amount and duration phrases both share; `MarchCopyTest` reads them under Robolectric.

## Gotchas

- Resource names are one namespace across modules: `android.nonTransitiveRClass=true` gives each module its own `R` class, so a clash compiles, but the merged APK holds one value per name and the dependency `app/build.gradle.kts` declares first wins silently. A module prefixes its own names (`chronicle_`, `map_`). Guard: `rg -No --no-filename 'name="[^"]+"' apps/android -g '**/src/main/res/values/*.xml' | sort | uniq -d` prints nothing.

- Robolectric (4.17, `feature:chronicle`'s, `feature:fief`'s, `feature:map`'s and `feature:signin`'s tests only; the Compose UI tests, `ChronicleLineTest`, `FirstFiefScreenTest`, `SignInScreenTest`, `SignUpScreenTest`, run on it with `ui-test-junit4` and `ui-test-manifest`) needs Java 21 for SDK 35 and above, and CI runs Java 17, so `src/test/resources/robolectric.properties` pins `sdk=34`; each module also sets `testOptions.unitTests.isIncludeAndroidResources`.

- A Compose UI test that asserts a cleared focus runs in touch mode (`setInTouchMode(true)` in a rule ordered before the compose rule, as `ArmySectionFocusTest` does): out of touch mode Android hands the cleared focus back to the first focusable, as a hardware keyboard would, and the test reads a field still focused.
- Never add a `package.json` here: pnpm takes every directory with one under `apps/*` as a workspace package.
- `local.properties` (`sdk.dir=...`) is gitignored and per machine; CI reads `ANDROID_HOME` from the runner instead.
- AGP 9 compiles Kotlin itself: no `org.jetbrains.kotlin.android` plugin. The Kotlin version comes from `kotlin-gradle-plugin` on `build-logic`'s classpath.
- detekt is 1.23.8 (stable, built against Kotlin 2.0) and runs beside Kotlin 2.4.21 because the `detekt` task parses sources without type resolution. Rules that need type resolution (`UnsafeCallOnNullableType`, for one) report nothing under `detekt`; review still catches `!!`.
- The Compose rules are `io.nlopez.compose.rules:detekt` 0.4.28, the last line built for detekt 1.23. From 0.5 on they target detekt 2.0 and load under 1.23 without error and without running a single rule; probe a new version with a public `@Composable` that emits a `Box` and has no `modifier` before trusting it.
- detekt 1.23.8 uses Gradle APIs deprecated for Gradle 10 (`ReportingExtension.file`, `Configuration.setVisible`); the build warns, nothing fails.
- The configuration cache is on (`gradle.properties`). A custom task reads only its declared inputs; both check tasks live in `build-logic/convention` (where detekt lints them; it never reads `.kts`), registered on the root project by `mygame.module.checks`, and gather their inputs in `gradle.projectsEvaluated`.
- `core:network`'s tests depend on `core:testing`, which depends on `core:network`; Gradle resolves it because only the test configuration closes the loop.
- The release key is the app's identity. Losing it means uninstalling the app on the phone before a build under a new key installs, and losing its local data with it: the stored session (the fief lives on the api, so signing in again restores it).
- Debug and release share `applicationId` `com.emm.mygame` but not their signature, so `adb install -r` of one over the other fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`: run `adb uninstall com.emm.mygame` first, which signs the player out.
- R8 is off for `release`. The APK goes only to the owner's phone, so its size buys nothing, while minifying needs keep rules for the generated client's kotlinx.serialization wrappers and Navigation 3's `@Serializable` keys, and a missed rule crashes only on the phone, in a screen the release check did not walk. Turning it on means those rules and the whole flow (map, chronicle, marches) run on a minified `localRelease`.
