# apps/android

The native Android client (ADR 034): Kotlin and Jetpack Compose, a renderer of what the api returns. A Gradle project of its own, outside the pnpm workspace. The rules: `.claude/rules/android-architecture.md`, `kotlin-style.md`, `android-testing.md`, `ui-components.md`.

## Commands

Run from `apps/android`. Every Gradle command runs as `taskpolicy -c utility ./gradlew …`, so an emulator and the other peers keep priority: a Gradle daemon keeps the priority it started with and later builds reuse it, so one run without the prefix leaves a full-priority daemon behind. CI's `ci.yml` runs plain `./gradlew`, since Linux has no `taskpolicy`.

- `taskpolicy -c utility ./gradlew detekt checkModuleBoundaries checkComposeFreeViewModels testDebugUnitTest assembleDebug` — the Android leg of the gate, exactly what CI's `android` job runs. Green before every commit that touches `apps/android`, on top of `pnpm gate`.
- `taskpolicy -c utility ./gradlew detekt` — detekt with the formatting (ktlint) and Compose rule sets, over every module and over `build-logic/convention/src/main/kotlin` (the root project's detekt source), never over `build/`, where the generated client lives. Thresholds live only in `config/detekt/detekt.yml`.
- `taskpolicy -c utility ./gradlew checkModuleBoundaries` — fails on any project edge the Modules table of `android-architecture.md` does not allow, on `:core:testing` reached through a configuration whose name does not start with `test` or `androidTest`, on a module missing from the table, and on `:core:projection` applying an Android plugin. The table is `allowedCoreEdges` and `allowedFeatureEdges` in `build-logic/convention/.../ModuleChecksConventionPlugin.kt`; a new module is a new entry there and in the rule.
- `taskpolicy -c utility ./gradlew checkComposeFreeViewModels` — fails on any line of a `*ViewModel.kt` or `*UiState.kt` under any module's `src/` that names `androidx.compose`.
- `taskpolicy -c utility ./gradlew testDebugUnitTest` — the unit tests of every module. `:core:projection` is a JVM module, so its `testDebugUnitTest` is an alias of `test` that the `mygame.jvm.library` convention registers.
- The peer's own emulator, the AVD `mygame-<name>` (`docs/agents/multi-session.md`, Isolation: emulators): `$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager create avd -n mygame-<name> -k "system-images;android-36;google_apis_playstore;arm64-v8a" -d medium_phone`; set `hw.gpu.enabled=yes`, `hw.gpu.mode=host` and `hw.ramSize=4G` in `${ANDROID_AVD_HOME:-$HOME/.android/avd}/mygame-<name>.avd/config.ini`; start it with `$ANDROID_HOME/emulator/emulator -avd mygame-<name> -port <port> -no-window -no-audio -gpu host` on an even port in 5560–5588 that `adb devices` does not list, and pass `-s emulator-<port>` to every `adb` command below. Ports 5590 and up belong to pichanga. `scripts/mygame-wave-close` stops it and deletes the AVD at close-out. _Why: `avdmanager` leaves the GPU off, so the emulator renders in software and crawls. Pichanga's 2026-11-04 benchmark, three cold boots per mode: `-gpu host` headless matched a window (under 0.3% janky frames) at about half the idle CPU and 1 GB less memory, while software rendering took about 5 cores under load. A fresh AVD boots in about 33 s, against 15 s after._
- `taskpolicy -c utility ./gradlew assembleDebug`, then `adb install -r app/build/outputs/apk/debug/app-debug.apk` and `adb shell am start -n com.emm.mygame/.MainActivity` — the app on a running emulator.
- Once per machine, the release key: `mkdir -p ~/keys`, then `keytool -genkeypair -v -keystore ~/keys/mygame-release.jks -alias mygame -keyalg RSA -keysize 4096 -validity 10000`, with the keystore outside the repo and backed up. `keytool` writes a PKCS12 keystore, which keeps one password for the store and the key, so `keyPassword` takes the same value as `storePassword`. Then four lines in `~/.gradle/gradle.properties`: `mygame.release.storeFile=/absolute/path/to/mygame-release.jks`, `mygame.release.storePassword=…`, `mygame.release.keyAlias=mygame`, `mygame.release.keyPassword=…`; or the environment variables `MYGAME_RELEASE_STORE_FILE`, `MYGAME_RELEASE_STORE_PASSWORD`, `MYGAME_RELEASE_KEY_ALIAS`, `MYGAME_RELEASE_KEY_PASSWORD`. A Gradle property wins over its variable.
- `taskpolicy -c utility ./gradlew assembleRelease`, then `adb install -r app/build/outputs/apk/release/app-release.apk` — the signed APK for a phone; `apksigner verify --print-certs` on it prints the key's certificate. With none of the four set it writes `app-release-unsigned.apk` and exits 0, so CI needs no secret; with only some set the configuration fails, naming all four. `versionCode` reads the Gradle property `mygame.versionCode`, then the variable `MYGAME_VERSION_CODE`, then 1; `app-distribution.yml` sets the variable to the run number on every `trunk` push that changes an Android input, and on a dispatch, and sends the signed build to Firebase App Distribution (`.claude/rules/github-workflows.md`).
- `taskpolicy -c utility ./gradlew assembleLocalRelease` — the release build type, signed the same way, pointed at `-Pmygame.apiBaseUrl` (default `http://10.0.2.2:3141/`) with `src/debug`'s network security config: the release build against a local api on the emulator. Its `applicationIdSuffix` makes it `com.emm.mygame.local`, so it installs beside the debug or release app: `adb install -r app/build/outputs/apk/localRelease/app-localRelease.apk` and `adb shell am start -n com.emm.mygame.local/com.emm.mygame.MainActivity`.

## Layout

- `app` — `MainActivity`, `AppNavigation` and `MyGameApplication` as the composition root (the repositories, `learning` among them, base URL, Keystore cipher, token file, `Dispatchers.IO`). Navigation is Navigation 3: `Destination` holds the `@Serializable` keys (`SignIn`, `SignUp`, `ForgotPassword`, `Town`, `School`, `Report`, `Review`, `LessonWords`), `rememberNavBackStack` keeps the back stack across recreation and process death, and `Navigator` is the only code that edits it (`NavigatorTest` pins every move): sign-up and the reset request (`ForgotPassword`) each open above sign-in only, so system back and each screen's link back to sign-in pop to it; signing in, signing up or a restored session leaves `Town` alone on the stack, and signing out leaves `SignIn`; `Review` draws `feature:review`'s `ReviewRoute`. `SignIn` carries `isSessionEnded`, `false` at a cold start and after *Salir*, `true` when the session ended under the player: `AppNavigation` runs `Navigator.followSessionEnds` over `MyGameApplication.sessionEnds.ended`, which calls `signedOut(isSessionEnded = true)` on each report, and a report while that sign-in is already alone on the stack changes nothing; `LessonWords` carries the `LessonId` it reads and `walked`, the lessons already opened on this walk. `openLesson` opens it above `Town`, `Report` or `School`, and from `LessonWords` or `Review` takes the top's place, so system back leaves the walk. `openReviews` opens above `Town`, `Report`, `School` or `LessonWords`, and `openSchool` from `LessonWords` leaves `Town` and `School` on the stack. `NavDisplay` decorates each entry with `rememberSaveableStateHolderNavEntryDecorator` and `rememberViewModelStoreNavEntryDecorator`, so every route's ViewModel is scoped to its entry and cleared when the entry leaves the stack; a new session's view models start fresh with no store to clear. `SignedInFrame` draws every signed-in screen. On any screen but `Town` it draws `MyGameHeader` with `MyGameBackLink` to the town under the status bar, and consumes the status bar inset. The town home draws its own `MyGameHeader`, the town's name and `label` in `meta`, then `TownDoors`, *School* and *Report*, which a player with no town never sees. Sign-out lives at the foot of the Report: `ReportViewModel` holds `SessionRepository`. While *Salir* waits, `ReportRoute` or `TownRoute` calls `Navigator.signingOut`: `areLinksEnabled` turns false, the back link draws disabled, `back()`, `openSchool`, `openLesson`, `openReport` and `openReviews` leave the stack unchanged (`openTown` has no guard), and `signedOut` enables them for the next session. The box that holds the screen fits inside the keyboard (`fitInside(WindowInsetsRulers.Ime.current)`) and consumes the navigation bars and the IME, so the IME inset is applied once, there, and a screen's `safeDrawingPadding` adds none: with the keyboard open the screen ends at the keyboard's top. Namespace and `applicationId` `com.emm.mygame` (`com.emm.mygame.local` for `localRelease`). `BuildConfig.API_BASE_URL`: debug `http://10.0.2.2:3141/` (the host's api from the emulator; cleartext allowed for that host only, by `src/debug`'s network security config), or the `-Pmygame.apiBaseUrl=http://10.0.2.2:<port>/` Gradle property for an api on another port, release `https://mygame.emm3000.com/api/` (the web's `/api` rewrite, ADR 031), `localRelease` the debug value with the debug network security config. `release` is signed only when the four `mygame.release.*` settings are present (`signingConfigs.findByName("release")`), and runs without R8: `isMinifyEnabled` and `isShrinkResources` are `false` (Gotchas).
- `feature:signin` — sign-in, sign-up and the reset request (MVI). A session the api accepts is `SignInEffect.SignedIn` or `SignUpEffect.SignedIn`, sent through each ViewModel's buffered `Channel`; the state stays `Submitting` (or `CheckingSession`), and `SignInRoute` and `SignUpRoute` call `onSignedIn` when they collect it. Every route collects its effects inside `withContext(Dispatchers.Main.immediate)`: on the composition's own dispatcher an effect taken from the channel just before the activity is recreated would be lost, and the form would stay `Submitting`. Each screen links to the other (`onSignUpOpen`, `onSignInOpen`), and `Navigator` moves between them. `SignInViewModel` takes `isSessionEnded` from the route's key and draws *Tu sesión ha terminado. Entra de nuevo en tu pueblo.* in a `MyGameInlineAlert` above the fields until the player submits. The fields carry the web's autofill types: sign-in's email `EmailAddress` and password `Password`, sign-up's email `EmailAddress`, and password `NewPassword` (with *Al menos 8 caracteres.* as its `supportingText`). `SignUpViewModel` sends the email and password once (a second tap while one waits is dropped), draws the api's `SignUpRefusal` beside the form and offers a retry when the api cannot be reached; it never checks a field itself. While a sign-in or a sign-up is in flight the link to the other screen does nothing (`canSwitchToSignUp`, `canSwitchToSignIn`), so a late answer cannot overwrite the token of a session the player opened on the other screen; the same guard holds sign-in's *¿Has olvidado tu contraseña?* link, drawn under the submit, which opens `ForgotPasswordRoute`. `ForgotPasswordScreen` (the web's `ForgotPasswordScreen`) reads *Recupera tu contraseña*, the field *Correo* (autofill `EmailAddress`) and *Enviar enlace*; `ForgotPasswordViewModel` sends the email as typed once (a second tap while one waits is dropped) and checks no field, leaving the shape to the api's 400. `Requested` replaces the form with *Si ese correo tiene una cuenta y está confirmado, te llegará un enlace que vale una hora.* (a polite live region); `MalformedEmail` draws *Escribe un correo válido, como nombre@ejemplo.com.* and `Unreachable` the *Unexpected* line, each in a `MyGameInlineAlert` beside the kept form, where *Enviar enlace* asks again. It has no effect channel: the only way out is the *Entra en tu pueblo* link, under the form and under the confirmation. The mail's link opens the web's new password screen; no deep link reaches the app.
- `feature:review` — the review, with its end states, labels and `SpanishLocale.kt`. The review screen (`ReviewRoute`, `ReviewViewModel`, `ReviewUiState`, `ReviewIntent`, no effect; `ReviewScreen`, `ReviewCardContent.kt`, `ReviewStepLine.kt`, `ReviewEnd.kt`) reads the player's reviews, `LearningRepository.reviews`, and draws, under *Repaso*: `Loading` (*Estamos leyendo tu repaso…*), `Failed` (*No hemos podido leer tu repaso.* with *Volver a intentarlo*), `NoCards` when `due` is empty and `nextDueAt` is `null` (*Aún no tienes palabras que repasar.*), `NothingDue` with *Siguiente repaso:* and `nextDueAt` in `finishLabelOf`'s form, projected with the gap to the read's `readAt`, repainted on `repaintDelay` and read again at zero (a failed read asks again a minute later), or `Reviewing`: *Por repasar: N* and the first card of `due`, in the api's order. A recognition draws the word, the frame, *¿Qué significa?*, the choices as `Role.RadioButton` rows (`ChoiceChosen` keeps the `ChoiceId`) and *Comprobar*, which sends the chosen id and nothing while none is chosen; a recall draws the gloss, the gapped frame, *¿Cómo se dice en inglés?*, the field *Tu respuesta en inglés* (its label is the field's content description; autocorrect off, capitalization none, *Done* checks, ADR 036 rule 9), *Pedir una pista* until a hint arrives and *Comprobar*, which sends the text as typed and nothing while the field is empty, drawn blocked with *Escribe tu respuesta para comprobarla.* as its state description; the field keeps at most `REVIEW_ANSWER_MAX_LENGTH` characters (100, `ReviewAnswerRequest.answer`'s `maxLength`, which `ReviewAnswerMaxLengthTest` reads from `../api/openapi.json`). One request at a time (`ReviewStep.Checking`, *Comprobando…*, or `Hinting`); the hint (*Empieza por «s» y tiene 6 letras.*, plural from `letterCount`) stays on the card until its rating; `NearMiss` keeps the typed text; `Correct` reads *Correcto.* and, with an `earnedSkill`, *Habilidad ganada: energía, nivel 1.* (the verdict's `level`, a `RaisedSkill` naming the town's resource, `TownResourceKind`, from `review_skill_resource_*`; a skill whose resource the client does not know is dropped and the verdict still drawn) and *+5 % de energía / h.*, drawn with or without a town (`SkillLine.ratePercent` is never null; only `ratePerHourBefore` and `ratePerHourAfter` are null while the player holds no town, ADR 040); `Wrong` reads *No es correcto.*, *Tu respuesta:* (the chosen gloss or the typed text) and *La correcta:* (the verdict's `gloss` for a recognition, its `word` for a recall) and *Esta palabra volverá en unos minutos.*; a rated answer re-reads the reviews before the verdict is drawn (the step stays `Checking`, a near-miss reads nothing), and *Siguiente* draws that re-read, or reads again from `Loading` when it failed. A `ReviewRefusal` stays beside the card with its catalog line, and `ReviewNotDue`, `UnknownChoice`, `WordNotHeld` and `UnknownWord` add *Volver a intentarlo*, which reads the review again; an outage draws the `review_unreachable` line. The review draws a due count, a progress line of `(walked + rated) / (walked + dueCount)`, `ReviewBlock`, the choices or the field, `ReviewStepLine`, the one ink pill and, on an unrated recall, the hint under it. `Reviewing.walked` counts the cards rated in this run, raised by `next()` and kept through a read, and gives the block its hue: a card that comes back takes a new one. A verdict is an icon and words in `ink` (`RIGHT_ICON`, `WRONG_ICON`), a near miss is `ink` on `surfaceSunken` with an `ink` border and no icon, as on the web; `MyGameInlineAlert` stays for refusals and an outage. The block is a merged polite live region, so a test finds its text and `BLOCK_HUE` on one node, and reads a text style with `useUnmergedTree`. A new `feature:<name>` needs only `settings.gradle.kts`: `checkModuleBoundaries` admits every `:feature:` module with the feature edges.
- `feature:town` — *Name your town* and the town home with its building work (MVI, #763, ADR 040). One `TownViewModel` reads `TownRepository`: `TownReadResult.NoTown` draws `Naming`, whose founding answer opens the home with no navigation; the home loops, drawing `core:projection`'s stocks and waiting `repaintDelay`, and reads again when the slot, the lesson or the season reaches its instant. A blocked level stays tappable, since the api's answer is the only verdict. A blank name is sent too: `BlankTownName` is the api's refusal, never the client's. `Naming` and `Failed` draw sign-out, a `MyGameTextButton` reading `town_sign_out`, for a player with no way to the Report: `SignOutTapped` cancels every read and mutation the screen started, draws `SigningOut`, awaits `SessionRepository.signOut` and sends `TownEffect.SignedOut`; `TownRoute` hands `onSigningOut` and `onSignedOut` to `Navigator`, as `ReportRoute` does. `Loading` carries none. The top padding is `step8` in every state but `Content`, which keeps `step2`. The town home draws `TownDoors`, `TownSkyline`, `StocksSection` (the stocks two by two, the people, the season), `BuildingWorkSection` and `PlacesSection`; #841 owns the next-step block. `contentAt` sorts the stocks by `TownResourceKind` and sets the school first among the places; `TownSkyline` keeps its own order, the one the hues follow, and takes its proportions from the web's: places 100 wide, 142 tall, a step of 72. `PlaceCard.isInWork` holds for the slot and the waiting list. `TownUiState.SeasonLine` is null until the api names a season, and it counts the season in force, not the next one. `feature:town` imports nothing of `feature:review`. Its resources carry the `town_` prefix.
- `feature:school` — the school (MVI, ADR 040): a `SchoolViewModel` reads `TownRepository` as `TownViewModel` does, draws the learning load, the lesson slot and the lessons, starts and stops a lesson, and reads again at the lesson's finish. A failed first read waits for the tap; the screen stops on background through `LifecycleStartEffect`. Its resources carry the `school_` prefix. The words screen (`LessonWordsRoute`, `LessonWordsViewModel`, `LessonWordsUiState`, `LessonWordsIntent`, `LessonWordsEffect`, `LessonWordsScreen`) reads `TownRepository` and `ReportRepository` and sends no write. `Reading` draws one word at a time from `Lesson.readings`; a lesson the town does not hold or with no reading draws `NothingToRead`. Either read unreachable draws `Failed`, and a failed re-read keeps the content and asks again a minute later. The loop re-reads at the lesson's finish, and `ScreenShown` after a hide re-reads silently, keeping the word's place, so a return from the reviews shows the rest. `wayOn` is `null` while the lesson runs; `wayOnOf` gives the first lesson of `readFirst` not in `LessonWalk.opened`, then the reviews. The school draws, in order: `ShownLesson` (the block and its pills) or `SchoolNextStep`, `LearningSection`, `LessonRows`, `LessonSlotSection`, `SkillsSection`. `SchoolUiState.Content.shown` picks the block's lesson as the web's `shownCardOf`: the selected one if unstudied, the first `Open` in the wire's order, the first unstudied. The block's hue is `blockHueOf(card.number - 1)`, the place in the curriculum. `selected` lives in `SchoolViewModel` and survives a read; `SchoolScreen` scrolls to the top when it changes. While a lesson runs, `SlotLine.Running` (`Busy` or `Done`) holds the ink pill *Read the words*, which names its lesson under another lesson's block, and the study pill is outlined. With no unstudied lesson, `SchoolNextStep` draws only the pill, to the reviews or the running lesson's words; #841 owns the block for that state. A block reason is `caption` in `warningInk`, hidden from TalkBack, since the pill's state reads it.
- `feature:report` — the Report (MVI, ADR 040): a `ReportViewModel` reads `ReportRepository` once, with no timer since `GET /report` carries no due instant, and *Cerrar las noticias* posts the close. A failed first read waits for the tap; a failed re-read keeps the content and retries every minute while shown, and stops on background. Its resources carry the `report_` prefix. `Content.firstUnread` is the first lesson of `TownReport.readFirst`: the button opens it, else the reviews. The Report draws the due count in a periwinkle `MyGameBlock` with its `MyGameButton` under it, never inside; with nothing due, a `MyGameCard` and no pill. The news title is `meta`, so a test finds it uppercased. Each news and each empty line sits under a `MyGameHairline`.
- `core:network`, `core:testing` — Android libraries; `core:designsystem`, `core:ui` — Android libraries with Compose (`core:ui` holds `IcuStrings.kt`, the ICU string helper, below, and the school path); `core:projection` — Kotlin JVM, holding the resource projection (`ResourceStock`), `FinishClock`, `Countdown` and `RepaintCadence`. Library namespaces are `com.emm.mygame` plus the module path (`com.emm.mygame.core.designsystem`).
- `build-logic/convention` — the convention plugins every module applies: `mygame.android.application`, `mygame.android.library`, `mygame.android.compose`, `mygame.jvm.library`, and `mygame.module.checks` on the root project. SDK levels (compile and target 37, min 26) and the JVM target (17) live in `ProjectDefaults.kt`.
- `gradle/libs.versions.toml` — every version, exact. `build-logic` reads the same catalog.
- `core:network` — `openApiGenerate` (openapi-generator Gradle plugin, `kotlin` generator, `jvm-retrofit2` with `kotlinx_serialization` and coroutines) generates `../api/openapi.json` as committed, with no rewrite, into `build/generate-resources/main`, wired into compilation by `addGeneratedSourceDirectory`; `openapi-generator-ignore` drops the generated `ApiClient`, auth and Gradle files, since `SessionRepository(...)` builds Retrofit itself. `number` maps to `kotlin.Double` and `integer` to `kotlin.Int`; the mapper turns an amount and a capacity into `Long` and keeps the rate as the `Double` the projection needs. Every union the api returns is a named component with a `discriminator`, and `generateOneOfAnyOfWrappers` turns each into a sealed interface with one wrapper per member, whose serializer picks the member by the discriminator's value; a value the spec does not list fails the decode. `enumUnknownDefaultCase` is on: an enum value the spec does not list decodes as `unknown_default_open_api`, so a server deploy that adds a value leaves every field the screen does not draw harmless; the mapper answers `Unreachable` for that case in a field the screen draws. The report's news is a union on `kind` too. A `kind` the spec does not list would fail the whole decode, so `KnownTownNewsConverterFactory`, registered before the kotlinx converter, drops from a `Report` body every news whose `kind` is not one of the generated news kinds; an unknown news is skipped, never `Unreachable`. No generated type crosses the module's public API (the repositories over them are `internal`); callers see `SessionRepository`, `TownRepository`, `ReportRepository`, `LearningRepository` and the results, refusals and value types beside them (`TownReadResult`, `TownFoundResult`, `TownLessonResult`, `ReportReadResult`, `ReviewsReadResult`, `SignInResult`, `SignUpResult`, `HeldTown`, `TownReport`, `LessonId`, `WordId`, `ChoiceId`, `TownResourceKind`, `TownBuildingKind`). `TownRepository` holds the town: `town` is a `StateFlow<HeldTown?>`, `read` answers `TownReadResult`, `found` posts the name and answers `TownFoundResult`, `startWork` and `stopWork` answer `TownWorkResult`, and `startLesson` and `stopLesson` answer `TownLessonResult`, mapped in `TownMapping.kt` and `TownLessonMapping.kt`. `ReportRepository` reads and closes the Report, mapped in `ReportMapping.kt`. `LearningRepository` holds the player's learning: `reviews` reads `GET /reviews` and answers `ReviewsReadResult.Read` with the `DueReviews` (`due` as `DueReview.Recognition` or `Recall` in the api's order, `nextDueAt`, and `readAt`, the instant the api derived the due list at, which the screen projects `nextDueAt` with the gap to; a refusal or an outage is `Unreachable`), mapped in `ReviewMapping.kt`; `hint` posts `/reviews/{wordId}/hint` and answers `ReviewHintResult`; `answer` posts `/reviews/{wordId}/answer` with the answer exactly as given, never trimmed (a recognition's chosen `ChoiceId`, a recall's typed text), and answers `ReviewAnswerResult.Answered` with the `ReviewVerdict` alone; a 409 is its `ReviewRefusal` (`ReviewNotDue`, `HintOnRecognition`, `UnknownChoice`, `WordNotHeld`, `UnknownWord`, or `Unrecognized`); a correct verdict's `RaisedSkill` names a `TownResourceKind` (money, food, power, material) and carries `ratePerHourBefore` and `ratePerHourAfter`, both null without a town, and a skill naming a resource the client does not know is dropped. `IsoInstantConverterFactory` writes an `OffsetDateTime` path parameter as `2026-11-02T15:30:00.000Z`, since Retrofit's `toString` drops zero seconds and the contract's `InstantSchema` wants them. `wireRefusal()` (`WireRefusal.kt`) decodes a refusal body for every repository: the generated `ApiError` is a union on `kind` (`BareApiError` for a kind with no fields, one member per kind with `params`), so it answers `WireRefusal.WithParams` with the generated union for one of the nine kinds with `params`, a malformed one `null` (`Unreachable`), and otherwise `WireRefusal.Bare` with the `BareApiError.Kind`, a kind the spec does not list decoding as `unknown_default_open_api` (`Unrecognized`); the repositories key their refusal maps by `BareApiError.Kind`. `kindsWithParams` names the nine kinds by hand, and `WireRefusalTest` holds it equal to the discriminator mapping of `apps/api/openapi.json` (every kind not mapped to `BareApiError`), read through the `mygame.apiSpec` system property that `core/network/build.gradle.kts` sets on every test task, so a tenth kind with `params` fails the suite instead of reading `Unreachable`. `SessionRepository.signUp` posts `/auth/sign-up/native` and stores the token as sign-in does; a 4xx answers its `SignUpRefusal` (`WeakPassword`, `EmailTaken`, `MalformedEmail`, or `Unrecognized` for another kind or an empty body), anything else `Unreachable`. `SessionRepository.requestPasswordReset` posts `/auth/forgot-password` with `{ email }` through `openingApi` and answers `PasswordResetRequestResult`: 202 `Requested`, 400 `MalformedEmail` (the api answers both with an empty body), any other status, an outage or a Keystore failure `Unreachable`; the email is never logged. `SessionRepository.signOut` posts `/auth/sign-out` with the stored bearer, on its own client whose call timeout is 5 s (sign-in and restore keep no call timeout, since a cold api can take longer), and deletes the token file in a `finally`, whatever the api answers, when it cannot be reached or when the call times out. A Keystore failure never reaches the call: `TokenStore.read` forgets the token, and the request goes without a bearer. `BearerInterceptor` is the one place the bearer is added. Every signed-in request (the town, report and learning repositories and `restore`) goes through `signedInApi` (`ApiClient.kt`): a 401 to a request that carried a bearer calls `TokenStore.clearIfHolding` with the token it sent, and only when the store still held that token does `SessionEnds.report` fire, so several 401s in flight end one session once, a 401 to a request sent without a bearer reports nothing, and a late 401 of an old session never clears a new one. `SessionEnds.ended` is a conflated `Channel` the composition root creates and passes to every repository factory. Sign-in, sign-up and the reset request (`openingApi`) go through `accountApi`, a client with no interceptor, so they never carry a bearer, even while a token is still stored after an `Unreachable` restore, and a 401 to them reports nothing. Sign-out goes through `signOutApi`, which adds the bearer but never reports, so a refused password or a refused sign-out never ends a session. The repository still answers its own `Unreachable` for the 401; the navigation away from the screen is `app`'s. `TokenStore.clear` and a forgotten token never leave a readable token behind: when the file's delete fails, the store empties the file and answers `null` until the next write. When the overwrite fails too, that `null` lives only in memory: after a restart the store reads the dead token again and sends it once, and that request's 401 ends the session. `TokenStore` keeps the token as AES/GCM ciphertext under the Keystore key of `KeystoreTokenCipher` in a file in `noBackupFilesDir`; its read and write are `internal`, and its `TokenCipher` is the seam a JVM test fakes.
- Tests: JUnit 4, Turbine, `kotlinx-coroutines-test` on every module's `testImplementation` (`UnitTests.kt` in the conventions); `core:network` tests the repository against OkHttp's `mockwebserver3`. `core:testing` holds `FakeSessionRepository`, `FakeTownRepository`, `FakeReportRepository`, `FakeLearningRepository` (counts the reviews reads in `readCount` and records each hinted `WordId` and each `AnswerRequest`), `FakeTokenCipher`, `MainDispatcherRule` and `TestClock`, which reads the `runTest` scheduler's virtual time so a `delay` advances it. A ViewModel that loops on the clock needs its scope cancelled before `runTest` ends (`backgroundScope.launch(start = CoroutineStart.UNDISPATCHED)` cancelling `viewModelScope`), or the test never finishes. `core:projection` reads the shared fixture `packages/domain/src/town/projection-cases.json` through the `projection.cases` system property its build sets, a declared test input; `readSharedCases` fails on an unset property, a missing file, an empty `cases` list or a case whose keys differ from the reader's. A JVM module cannot consume `core:testing`, so its readers live in its own test sources.
- `core:designsystem` — the Townword Design System's tokens (#756), generated from the web's `apps/web/src/design/tokens.ts` by `pnpm --filter @mygame/web tokens` and never edited by hand; the web suite fails on a drift (`apps/web/CLAUDE.md`): `MyGameColors` (one field per `palette` token, kebab-case to camelCase, 20 fields, `lightColors` (Day) and `darkColors` (Night) with the same names), `MyGameTypeFamilies.sans` (Schibsted Grotesk, bundled as the variable TTF `res/font/designsystem_schibsted_grotesk.ttf`, no italic, one `Font` per weight `typeScale` uses, 400, 500, 600, 700 and 800, each pinned with `FontVariation.weight`; its SIL OFL 1.1 ships as `src/main/assets/designsystem_schibsted_grotesk_OFL.txt`, since `res/font` accepts only font files; no font is downloaded at run time), `MyGameSpacing` (`step<n>` for `spacing[n]`), `MyGameRadii`, `MyGameTransitions` (the four durations in milliseconds, the `standard` and `exit` easings and `track`), `MyGameTypography` (one `TextStyle` per `typeScale` style, line heights in `em`, `numeral` with tabular figures, `reading` with `TextMotion.Animated`, ADR 043's device check; `withTabularFigures`, hand-written in `TabularFigures.kt`, gives another style tabular figures), `MyGameSizes` (the `size` family but `measure-reading`, which has no `ch` in Compose, `dash` for `dashedFrame` among them), `MyGameStrokeWidths` (`hairline`, `control`, `mark`, `focus` in dp and `ICON`, the path stroke on the 24 viewport); `MyGameColorsContrastTest` holds every text pair at 4.5:1 and every boundary and graphic at 3:1 in both themes, the artifact's Contrast table plus the pairs the screens draw, with the disabled `lineStrong` on `surfaceSunken` label exempt under WCAG 1.4.3. ## Gotchas

- Every `res/values/strings.xml` (`app` and the five features) is generated from `packages/catalog/es.json` by `pnpm --filter @mygame/catalog generate` (`packages/catalog/CLAUDE.md`), and its drift test fails `pnpm gate` on a hand edit: a string changes in `es.json` under `android.<module>.<resource_name>`, then `generate` runs. Spanish sits in `values/`, never a `values-es/`. A string is an ICU MessageFormat pattern with named arguments, never a printf one, and a `<plurals>` is one string holding an ICU plural (`{count, plural, =1 {Contrataste 1 camión.} other {Contrataste {count, number,0} camiones.}}`), so there is no `R.plurals`, `pluralStringResource` or `getQuantityString`. A string with arguments, a plural or an ICU quote (`''`) is read through `core:ui`'s `IcuStrings.kt`, which formats with `android.icu.text.MessageFormat` in Spanish: `icuStringResource(R.string.slot_level, "level" to level.toString())` in a composable, `Resources.getIcuString(...)` beside it, `String.formatIcu(...)` on a pattern already read (`spanishListOf`); a plain string stays `stringResource(id)`. An argument that once filled `%d` passes its `toString()`, so ICU's Spanish grouping never touches it, `%02d` its `toString().padStart(2, '0')`; a plural selector passes the number, and the plural writes its count as `{count, number,0}`, never `#`, so ICU's Spanish grouping never reaches it either (`10000 camiones`, as printf wrote it; `packages/catalog/src/es.test.ts` fails on a `#` in an Android key, `ReportCopyTest` pins the Report's copy).

- Resource names are one namespace across modules: `android.nonTransitiveRClass=true` gives each module its own `R` class, so a clash compiles, but the merged APK holds one value per name and the dependency `app/build.gradle.kts` declares first wins silently. A module prefixes its own names (`report_`, `school_`). Guard: `rg -No --no-filename 'name="[^"]+"' apps/android -g '**/src/main/res/values/*.xml' | sort | uniq -d` prints nothing. A file resource (a drawable) is named by its file, so `core:designsystem` prefixes its own with `designsystem_`; guard: `fd -p -g '**/src/main/res/drawable*/*.xml' apps/android -E build -x basename {} | sort | uniq -d` prints nothing.

- Robolectric (4.17, `app`'s, `core:designsystem`'s, `feature:report`'s, `feature:review`'s, `feature:school`'s, `feature:signin`'s and `feature:town`'s tests only; the Compose UI tests, `ReviewScreenTest`, `ReportScreenTest`, `SignInScreenTest`, `SignUpScreenTest`, run on it with `ui-test-junit4` and `ui-test-manifest`) needs Java 21 for SDK 35 and above, and CI runs Java 17, so `src/test/resources/robolectric.properties` pins `sdk=34`; each module also sets `testOptions.unitTests.isIncludeAndroidResources`.

- Never add a `package.json` here: pnpm takes every directory with one under `apps/*` as a workspace package.
- `local.properties` (`sdk.dir=...`) is gitignored and per machine; CI reads `ANDROID_HOME` from the runner instead.
- AGP 9 compiles Kotlin itself: no `org.jetbrains.kotlin.android` plugin. The Kotlin version comes from `kotlin-gradle-plugin` on `build-logic`'s classpath.
- detekt is 1.23.8 (stable, built against Kotlin 2.0) and runs beside Kotlin 2.4.21 because the `detekt` task parses sources without type resolution. Rules that need type resolution (`UnsafeCallOnNullableType`, for one) report nothing under `detekt`; review still catches `!!`.
- The Compose rules are `io.nlopez.compose.rules:detekt` 0.4.28, the last line built for detekt 1.23. From 0.5 on they target detekt 2.0 and load under 1.23 without error and without running a single rule; probe a new version with a public `@Composable` that emits a `Box` and has no `modifier` before trusting it.
- detekt 1.23.8 uses Gradle APIs deprecated for Gradle 10 (`ReportingExtension.file`, `Configuration.setVisible`); the build warns, nothing fails.
- The configuration cache is on (`gradle.properties`). A custom task reads only its declared inputs; both check tasks live in `build-logic/convention` (where detekt lints them; it never reads `.kts`), registered on the root project by `mygame.module.checks`, and gather their inputs in `gradle.projectsEvaluated`.
- `core:network`'s tests depend on `core:testing`, which depends on `core:network`; Gradle resolves it because only the test configuration closes the loop.
- The release key is the app's identity. Losing it means uninstalling the app on the phone before a build under a new key installs, and losing its local data with it: the stored session (the town lives on the api, so signing in again restores it).
- Debug and release share `applicationId` `com.emm.mygame` but not their signature, so `adb install -r` of one over the other fails with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`: run `adb uninstall com.emm.mygame` first, which signs the player out.
- R8 is off for `release`. The APK goes only to the owner's phone, so its size buys nothing, while minifying needs keep rules for the generated client's kotlinx.serialization wrappers and Navigation 3's `@Serializable` keys, and a missed rule crashes only on the phone, in a screen the release check did not walk. Turning it on means those rules and the whole flow (sign-in, town, school, Report, review) run on a minified `localRelease`.
